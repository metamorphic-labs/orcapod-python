## The bug

`GroupBy(by)` built `tuple(by)`, so a bare string was split into characters: `stream.group_by("subject_id")` grouped on the columns `'s'`, `'u'`, `'b'`, ... and failed with `GroupBy: ['s', 'u', 'b', ...] are not tag columns`. A one-character name (`group_by("g")`) worked by accident, which hid the trap in small examples.

## The fix: one rule for column-name arguments

`schema_utils.column_names(columns)` is the one rule: a bare string is one column name; any other iterable gives its elements, in order; `bytes`, a non-iterable and a non-string name raise `TypeError`. Every argument that takes a collection of column names now reads it through it:

| Entry point | Bare string | Through `column_names` |
|---|---|---|
| `GroupBy(by)`, `stream.group_by` | one name (was: split, **fixed**) | yes |
| `SelectDataColumns`, `DropDataColumns`, `SelectTagColumns`, `DropTagColumns`, `SelectColumns`, `DropColumns` and their stream methods | one name (unchanged) | yes, via `_canonical_columns` |
| `DropNulls`, `stream.drop_nulls` | one name (unchanged) | yes |
| `TagBy`, `stream.tag_by` | one name (unchanged; a set is still refused) | yes |
| source `tag_columns` | one name (unchanged) | yes, via `_normalize_column_list` |
| source `record_id_columns` | one name (unchanged) | own check: a set is refused (key order) |
| source `tag_only_columns` | one name (unchanged) | own check: also takes `True`/`False` |
| `MapTags`, `MapData`, `MapColumns`, `AddTags`, `PolarsFilter` constraints | not applicable (mappings) | |
| `Batch`, `Join`, `MergeJoin`, `SemiJoin` | not applicable (no column-name argument) | |
| `Pick`, `Index` | not applicable (one `column: str`) | |

No other operator split a string.

## Identity

`GroupBy("x")` has the identity structure, content hash, pipeline hash, saved config (`{"by": ["x"]}`) and stream hashes of `GroupBy(["x"])`. A list or tuple keeps its order and its identity, so no golden value moves (golden suite unchanged and passing). No stored identity moves either: a config always saved `by` as a list, and the old code with a bare multi-character string only built a valid pipeline if every character of the string was itself a distinct tag column (`group_by("ab")` over tags `a` and `b`), so a saved pipeline that loads differently would need that coincidence; for any other string the old code raised `InputValidationError` at validation.
