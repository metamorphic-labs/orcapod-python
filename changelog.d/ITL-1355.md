### Changed

- **`Rejoin` matches rows on every column its inputs share and no longer refuses on what
  rows hold** (ITL-1355). It is an inner join on the system-tag columns, a tag several
  inputs have, the source info of a shared data-tag and the data context, compared as
  `Join` compares its keys (NaN equals NaN, `-0.0` equals `0.0`; a null system tag matches
  nothing, a null in any other shared column equals a null). A row that matches nothing is
  left out. Behaviour change: inputs that `Rejoin` refused with `InputValidationError` now
  give fewer rows instead:
  - a shared tag, or a shared data-tag's source info, that differs on rows of one origin
    row: those rows are left out, and a new `RejoinDifferingColumnWarning` (from
    `orcapod.errors`) names the columns, once per operator and set of columns;
  - rows of different data contexts: they match nothing (the same warning names the data
    context), and each result row keeps its own data context;
  - a null in a system-tag column: the row matches nothing;
  - equal values in different bits (`-0.0` and `0.0`, NaNs of different payloads): they
    match, and the shared column keeps the values of the first input that has it, in
    Rejoin's canonical input order (by pipeline hash; inputs with equal pipeline hashes
    stay in argument order);
  - an input holding two rows of one origin row: no longer refused. System tags are
    assumed unique, as every source makes them; repeated ones pair in row order, each row
    at most once, in time linear in the rows.

  `Rejoin` still refuses what the inputs' columns show: system-tag columns that differ or
  are absent, a shared column whose Arrow type differs, overlapping data columns. For every
  input it accepted before, the result is unchanged: the same rows in the same order, the
  same values, types and hashes.
