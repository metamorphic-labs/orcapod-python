### Breaking changes and migration

- The default source id of a `PostgreSQLTableSource` names the server the connection reached
  (ITL-1267): `postgresql_table:<host>:<port>/<database>.<schema>.<table>` (was
  `postgresql_table:<database>.<schema>.<table>`), so one database, schema and table name on
  two servers gives two ids. The host is the name or address as libpq reports it, a host name
  in lower case, an IPv6 address in brackets in its exploded form (no `::`), a Unix-domain
  socket directory as given (a Windows one with its drive too); the port is always the number used (without one in the DSN, a
  service file's, else `PGPORT`, else libpq's compiled default, normally `5432`).
  No user name, password or other connection parameter enters the id. The system-tag values
  and source-info tokens of rows read from PostgreSQL without a `source_id` change with it; a
  `source_id` you give is used as before, and a saved job keeps the id it was saved with.
- A PostgreSQL source whose DSN, `PGHOST` / `PGHOSTADDR` setting or service file names several
  servers (`host=a,b`) has no default source id and raises `ValueError` unless it is given a
  `source_id`: the server reached can change from one connection to the next. So does one
  whose parameters give a host beside a different `hostaddr` (`host=db.example.org
  hostaddr=192.0.2.1`), each from the DSN, a service file or the environment, as libpq takes
  them: the connection is sent to the address, so the host name does not name the server
  (two spellings of one IP address, compared by value, are one address). A host that would put
  `::` in the address (a socket directory holding it or ending with `:`) gives no default either. A `hostaddr` given alone names the server by that
  address. A database, schema or table name holding `/` has no default either, as one holding
  `.` already had.
- `orcapod[postgresql]` requires psycopg 3.1.17 or later (was 3.0). The default PostgreSQL
  source id relies on psycopg resolving a single host name of the DSN or `PGHOST` itself and
  passing the address to libpq as `hostaddr`, which `Connection.connect` does from 3.1.17
  on; with an earlier psycopg, a service file's `hostaddr` beside a host name would be the
  address used while the id named the host.
