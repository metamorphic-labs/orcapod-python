### Breaking changes and migration

- No identity depends on the order of a stream's columns (ITL-1246, ITL-1227; developer,
  November 18, 2026: "nothing should depend on tag order"). The identities of streams with
  data-tags are now settled and freeze with data context v1 at the 0.4.0 release. This
  replaces the "may still change" note of the data-tag entries.
  - A function pod called on a stream with data-tags (`pod(stream)`, a `FallThroughPod`)
    holds its data-tags as a set of sorted names. Before, it held them in the input's tag
    order, which came from `tag_columns` or, after an operator, from the table's physical
    layout. Now its content and pipeline hash, its job node's hashes and its pipeline table
    path are the same for every order. `FallThroughPod.fall_through_tags`, the pod's config
    and a saved job's `fall_through_tags` list the names sorted. The output still lists the
    data-tags first, in the input's tag order. A fall-through node whose input listed two
    or more data-tags out of name order gets a new pipeline table path. Its results are the
    plain pod's and are not recomputed.
  - A raw `ArrowTableStream` (one with no producer) hashes its whole identity table once,
    with its rows in a canonical order, and holds its tag columns and data-tags as sorted
    names. The table covers every column group but `_content_hash`.
  - The canonical order is a value sort: the user tags in name order, then every other
    column in name order, each only when its type is on a closed list. Rows still tied are
    ordered by their own row hash. The specification is in `docs/reference/hashing.md`.
  - So the same rows in any order, under any order of `tag_columns`, `data_tags` or
    system-tag columns, have one content hash. A duplicated row counts twice, and a stream
    with no rows still commits to its columns.
  - Before, the rows were sorted by the tags in tag order and the system tags in column
    order. A stream with no tag and no system tag could not be hashed. Rows tied on every
    tag, or with a list tag, hashed in their given order.
  - A raw stream's content hash moves only where that order differed. Among the pinned
    values, only `pipeline:list_tag_producerless_stream.as_given` moves. Sources, operator
    results and node outputs hash as before.

### Fixed

- A raw `ArrowTableStream` with no tag column and no system-tag column has a content hash.
  Before, it raised `ArrowInvalid` (nothing to sort by).
