### Changed

- **Function and side-effect job nodes work on their input's Arrow table** — on the sync
  path, where its input's table is provably its rows' (exactly a table stream, in the
  node's data context, with system tags and columns its rows would not retype), a
  function job node takes each input row's entry id from slices of that table instead of
  tables built from the row's values, by the same definitions (one preimage statement,
  one input data hash, `data_table_content_hash`); hands the library's row-blind
  observers views of its input rows, made only when read (any other observer receives
  the rows themselves); gives a stored result the id it was stored under by a shallow
  copy; and builds its output with the rows of stored results taken from the stored
  table. A side-effect job node hands on its input's table at the rows it passed on,
  under the same condition. Any other input takes the row path as before. Every output,
  stored row, entry id, observer event and error is as before. Third and fourth
  stages of the table transport between job nodes
  (`docs/dev/specs/itl-1347-job-table-transport.md`). (ITL-1361)
