### Changed

- The `ray` extra now requires `ray[default]>=2.60.0,<3`, no longer exactly `ray[default]==2.48.0`;
  the dev group follows, and `uv.lock` holds ray 2.60.0 (ITL-1210). Since Ray 2.59, a local
  `ray.init()` (no cluster address, which is what `RayExecutor` calls when you give it no
  `ray_address`) turns on Ray's token authentication and writes a token to
  `~/.ray/auth_token` if none exists. Set `RAY_AUTH_MODE=disabled` to opt out. Connecting to
  a remote or multi-node cluster is unchanged.

### Known limitations

- With Ray 2.54 or later, a driver started with `uv run` from a project whose version comes
  from version control (hatch-vcs or setuptools-scm, such as an Orcapod source checkout) hangs
  on its first `RayExecutor` call: Ray rebuilds the project on its workers without `.git`, and
  the workers never start. Set `RAY_ENABLE_UV_RUN_RUNTIME_ENV=0`, or start the driver with
  `python`. See the troubleshooting page. A driver started with `python`, and a project with a
  fixed version, are not affected (ITL-1210, ITL-1213).
