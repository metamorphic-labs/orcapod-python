### Added

- A `Filter` step changes only which rows flow (ITL-1378): its output has its input's
  columns, Arrow types, nullability, system tags, source info and row order, and every
  value passes through bit for bit (the rows are taken with an Arrow mask, with no Polars
  round trip). `col(c).is_not_null()` keeps the rows but does not narrow `T | None` to
  `T`; `drop_nulls(c)` does. A filter whose condition does not fit its input's Arrow types
  (an integer outside its column's range, a naive datetime for a zoned column) raises
  `InputValidationError` when it is applied, on the sync and the async path alike.
