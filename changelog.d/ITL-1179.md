### Breaking changes and migration

- In the Arrow tables Orcapod builds (streams, rows, tag and data datagrams, preimages, the
  tables behind default source ids), `-0.0` now hashes as `0.0` and every NaN (any sign or
  payload, quiet or signalling) as the ordinary NaN, as Orcapod already matches float keys
  (ITL-1251, ITL-1179). A row that differs from a stored one only in the sign of a zero or
  the bits of a NaN has the same hash and reuses the stored result. Stored values keep
  their bits.
- What changes, exactly (ITL-1179):
  - The hash of an Arrow table Orcapod builds that holds `-0.0` or a NaN other than the
    ordinary one, and every hash built on it (two golden values moved, both of a
    signalling-NaN `GroupBy` key).
  - The hash of a pyarrow `Table` or `RecordBatch` given as a value (a function default,
    an operator argument, a field of a user class), and of every structure that contains
    one: it now carries the label `arrow_strict_v1` instead of `arrow_v1`, with the same
    digest bytes, and the enclosing hash embeds the label. No golden value holds one.
  - The digests of the two dictionary inputs listed under "Changed" below.

  Every other hash is unchanged: the hashes of Orcapod's tables without `-0.0` or a
  non-ordinary NaN, and every hash that contains no pyarrow table given as a value.

### Changed

- Orcapod requires `starfix>=0.6.0,<0.7`, the Rust implementation of starfix (wheels for
  Python 3.10 and later on macOS, Linux x86_64 and aarch64, and Windows x86_64), in place of
  the pure-Python starfix-python 0.5.0 (ITL-1179). With the float options off, its digests
  are byte-identical to 0.5.0's, except two inputs starfix-python 0.5.0 hashed wrongly or
  refused: a dictionary over a sliced nested fixed-size list (ITL-1223) and a
  dictionary whose empty dictionary has no offsets buffer. Hashing a flat table is about
  eight times faster.
- Orcapod hashes with starfix's `normalize_negative_zero` and `normalize_nan` explicitly on
  for its own tables and explicitly off for library values, through one module
  (`hashing/starfix_digest.py`). Library values (numpy, torch, pandas, Polars) and the
  semantic hasher's Python floats keep the strict rule: `-0.0` and NaN payloads count.
- A pyarrow `Table` or `RecordBatch` given as a value is hashed strictly under its own label,
  `arrow_strict_v1` (it was `arrow_v1`, with the same digest).
- A null in a top-level column declared non-nullable is still refused with `ValueError`; the
  message is now starfix 0.6's ("Column 'x' is declared as non-nullable but contains null
  values").
