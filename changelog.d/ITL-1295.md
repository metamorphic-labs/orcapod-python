### Fixed

- **A function node's stored results read back exactly as they were stored.** Every read
  of stored results (`node.as_source()`, a second run of a job over the same database,
  `run(load_only=True)`, a saved and loaded job) carried every column through Polars.
  A user could see a `date64` tag read back at midnight (also inside a list or a
  struct); a join of the reused node's results with another input finding no rows on the
  second run although it found them on the first; a node added downstream storing the
  changed value; duplicate pipeline entries recorded on every such run; and, with a
  `decimal256` tag, the second run crashing the process. Now only the bookkeeping columns
  pass through Polars, and every value is taken from the stored tables. No hash, entry id
  or stored table changes. (ITL-1295)
