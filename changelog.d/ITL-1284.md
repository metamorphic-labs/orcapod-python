### Breaking changes and migration

- **`Join` and `SemiJoin` refuse a join key whose type has no rule for matching** (a map,
  an interval, a union, a list view, or a list or struct holding one) with
  `InputValidationError` naming the column, on both the sync and the async path (when
  rows are matched; also by `head()` of a stream with no rows). Before, the sync path
  failed with an error from Polars or Arrow, while the async path matched such keys. Join
  on other tags (drop the tag from one input, `drop_tag_columns`). (ITL-1284)

### Fixed

- **`Join` and `SemiJoin` emit every value exactly on the sync path.** Polars now only
  decides which rows match, from the prepared join keys and row numbers; every output
  column is taken from the input's Arrow tables. Before, every column went through Polars
  and back: a `date64` value off midnight came back at midnight (as data and as a key, in
  a list and in a struct), and a `decimal256` column made Polars panic, ending the process;
  a map or interval data column failed. The sync path now agrees with the async path for
  these types. Results change only for inputs holding such values; no golden value moves.
  (ITL-1284)
