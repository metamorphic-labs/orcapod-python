### Fixed

- The file hash cache no longer returns a hash made with another algorithm. A cache entry was
  keyed by the file's path, modification time and size only, so after
  `orcapod warm-cache --algorithm md5` the default (SHA-256) file hash returned the MD5
  value whenever caching was on, changing the identities and stored values a file enters.
  `FileHashKey` now carries the algorithm's hash label (`label`), and the in-memory, SQLite
  and PostgreSQL cachers return an entry only for the same label; an entry of another
  algorithm is a miss, and `warm-cache` counts it as not cached. Stored cache tables keep
  their layout (the stored hash already starts with its label); a file hashed with a second
  algorithm replaces the first algorithm's entry. A file content hasher now declares the
  label of its hashes (`hash_label`).
- A file hash cacher's `put` refuses (`ValueError`) a hash whose label is not the key's, or
  whose digest is not that algorithm's length, so a store never holds a value under another
  algorithm's key; a stored value that is not exactly `<label>:<digest of that length>` is read
  as a miss.
