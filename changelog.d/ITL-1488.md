### Fixed

- File hash caches now key entries by path, modification time, size, and algorithm.
  Hashes for different algorithms coexist. A hasher declares its hash label through
  `FileContentHasherProtocol.hash_algorithm`, and the cache key carries it in the
  provisional `FileHashKey.algorithm` field.
- A cache put raises `ValueError` for a mismatched label, an invalid digest length,
  or a different well-formed hash already stored under the same key. Putting an
  identical hash preserves its timestamp. SQLite and PostgreSQL treat malformed
  stored values as misses. The next valid put for the same key replaces the
  malformed value, refreshes its timestamp, and logs a warning naming the file
  and algorithm.

### Changed

- Scripts can now detect per-file errors, including `--force` conflicts, through the `orcapod warm-cache` exit status `1`.

### Breaking changes and migration

- SQLite and PostgreSQL use `file_hash_cache_v2` (schema version 2) and leave the
  previous `file_hash_cache` table untouched. The old SQLite migration helper
  was removed. ITL-1535 tracks migration of both older SQLite layouts (with and
  without `cached_at`). Until migration is available, let the next pipeline run
  or `orcapod warm-cache` hash the files once more to fill the new table.
