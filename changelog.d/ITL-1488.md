### Fixed

- File hash caches now key entries by path, modification time, size, and algorithm.
  Hashes for different algorithms coexist. A hasher declares its hash label through
  `FileContentHasherProtocol.hash_algorithm`, and the cache key carries it in the
  provisional `FileHashKey.algorithm` field.
- A cache put raises `ValueError` for a mismatched label, an invalid digest length,
  or a different hash already stored under the same key. Putting an identical hash
  is a no-op. Malformed stored values are cache misses.

### Changed

- Scripts can now detect per-file errors, including `--force` conflicts, through the `orcapod warm-cache` exit status `1`.

### Breaking changes and migration

- SQLite and PostgreSQL use `file_hash_cache_v2` (schema version 2). The previous
  `file_hash_cache` table is preserved and the cacher uses the new table. Until
  migration support is available (ITL-1535), let the next pipeline run or
  `orcapod warm-cache` hash the files once more to fill the new table.
