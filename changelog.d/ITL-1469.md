### Fixed

- A pipeline or job accepts one source object per content hash. Capture, binding,
  loading and execution reject distinct objects with the same hash, even if
  their rows agree. Build a source once and reuse it, or give each source its own
  source ID. Rebinding replaces a slot's source, and loading shares one rebuilt
  object across slots with identical source configurations.
- Sources with the same source ID must agree on their Arrow schema and key
  columns, including when they occupy different slots.
- Capturing another job's source slot or a standalone slot keeps the source
  object held at capture time. A capture refused by any active pipeline or job
  leaves all their graphs unchanged.

### Known limitations

- ITL-1506 tracks distinct readings of one dataset in distinct slots. ITL-1531
  tracks sources that read their rows later. ITL-1553 tracks accepting distinct
  objects that represent the same source.
