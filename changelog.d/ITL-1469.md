### Fixed

- A pipeline or job accepts one source object per content hash. Capture, binding,
  loading and execution reject distinct objects with the same hash, even if
  their rows agree. Build a source once and reuse it. Distinct IDs separate
  sources only when the ID contributes to the content hash. Rebinding replaces
  a slot's source, and loading shares one rebuilt object across slots with
  identical source configurations.
- Sources with the same source ID must agree on their Arrow schema and key
  columns, including when they occupy different slots. For tag-copy sources
  over a bound proxy, registration uses the live Arrow types.
- A capture refused by any active pipeline or job leaves all their graphs
  unchanged.
- Direct reads and job and node runs recheck source binding dependencies.
  If an operator or wrapper introduces a forbidden dependency after binding,
  they raise `SourceSpecMismatchError` before reading sources.
- Bindings to stored results reject cycles across jobs and name the slots
  involved. Pipeline capture and compilation also reject circular wrapper inputs.

### Known limitations

- ITL-1506 tracks distinct readings of one dataset in distinct slots. ITL-1531
  tracks sources that read their rows later. ITL-1553 tracks accepting distinct
  objects that represent the same source.
- As a stopgap pending ITL-1559, a job refuses foreign and standalone bindable
  slots (`SourceJobNode`), including through streams built from them. Pass the
  source itself, or use `node.as_source()` for another job's stored results.
  Schema-only `SourceNode` declarations still create independent slots.
- The ITL-1559 stopgap also refuses prebuilt streams over the receiving job's
  own slots. Build the step inside the job from its slot, or pass the source
  itself.
- Binding a slot to a source or stream that depends on any bindable slot or
  any node of its own job raises `SourceSpecMismatchError` (ITL-1559). A
  refused batch leaves all bindings intact. Pass the underlying source, or
  use another job's `node.as_source()` for stored results.
- Reassigning an invocation's upstreams is unsupported after capture.
  Rewiring an operator can leave stale rows in direct reads (ITL-1586).
