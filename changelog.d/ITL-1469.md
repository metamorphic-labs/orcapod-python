### Fixed

- Pipeline capture and job binding reject two in-memory sources that share a
  source ID and schema but contain different rows. With different key columns
  the rows are compared without their record IDs, as a multiset of tags and
  data. A node's `run()` checks the sources it reads as `job.run()` does. The
  error names the conflicting steps or slots. Job binding and loading also
  reject different schemas at a shared source ID.

### Known limitations

- Sources that share a source ID and schema but have different key columns are
  refused at capture, binding (into any slots), loading and run (`job.run()`
  and a node's `run()`). The error reports a difference only in key columns
  when all sources hold the same rows in memory.
  ITL-1506 tracks the design for using different key columns under one source
  ID. The row comparison only applies to sources that hold their rows in
  memory. ITL-1531 tracks sources that read their rows later.
