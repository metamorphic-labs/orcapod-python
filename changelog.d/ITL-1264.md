### Breaking changes and migration

- A dictionary-encoded column is refused (ITL-1264, ITL-1277). Dictionary-encoded columns are
  not currently supported in Orcapod, tags and data alike. A column whose Arrow type is a
  `dictionary`, or holds one inside it, raises `InputValidationError` when a source or a
  stream is built. This covers a tag, a data-tag and a data column, and a dictionary inside a
  list, a list view or a struct field. The message names each such column with its role, its
  type and the type it decodes to, and says how to decode it.
- Before, a dictionary tag was accepted and failed later and far from the cause: in
  `as_table(all_info=True)`, a filter, `Batch`, `GroupBy` or a join. Or it ran through a job.
  A dictionary data column was accepted with the Python type `Any`, which a typed function
  refused and some filters and joins failed on.
- Such columns come from an Arrow table of your own, a pandas `Categorical` of strings, and a
  polars `Categorical` or `Enum`. Decode the column first:
  - with pyarrow, cast the column to the fully decoded type the error message gives. For a
    plain dictionary column that is `column.type.value_type`. For a struct with a dictionary
    field it is, for example, `pa.struct([("k", pa.string()), ("n", pa.int64())])`.
  - three kinds need a step first: a dictionary whose values hold a dictionary (decode the
    top level of each chunk with `dictionary_decode()`, then cast), a list view (cast it to a
    large list of the decoded items) and a run-end-encoded column (cast its values, then
    expand the runs with `pyarrow.compute.run_end_decode`). The troubleshooting page gives
    each call.
  - with polars, `df = df.with_columns(pl.col(name).cast(pl.String))`.

  When you replace the column, keep its field
  (`table.set_column(i, field.with_type(decoded), column)`), so its nullability and
  metadata stay. Or keep a data frame whole as a value in a cell: a data frame in a cell (a
  library value) is not a dictionary column and is accepted as before.

### Changed

- `GroupBy` no longer reads a dictionary-encoded float key by the bits of its values, as
  ITL-1234 describes. Such a key is now refused when its source or stream is built, so that
  branch is removed.
