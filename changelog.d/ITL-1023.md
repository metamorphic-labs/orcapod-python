### Breaking changes and migration

- A source's declared tag columns are now referential by default (ITL-1023, specification
  "Orcapod v0.4 — Referential Tags"): each is also a data column of the same name, stored
  once, so a function can read it and joins and groups use it as a tag. A script run
  unchanged gets new schemas and hashes for such sources. Pass `tag_only_columns=[...]` (or
  `tag_only_columns=True`) to keep tags plain, exactly as before; every existing golden hash
  is unchanged under that option.

### Added

- `tag_only_columns` on `DictSource`, `ArrowTableSource`, `CSVSource`, `DataFrameSource`,
  `DeltaTableSource`, the database sources and `SpiralDBTableSource`.
- `Join` merges the data columns of a referential tag both inputs join on into one column;
  plain with referential gives a referential tag. `GroupBy` keeps a referential key scalar
  in both roles and makes a non-key the same list in both roles.
- `MapTags` renames a referential tag in both roles; `tag_only=True` renames the tag only.
  `MapData` is a data-only move.
- Removing the data column of a referential tag (`SelectDataColumns`, `DropDataColumns`)
  leaves a plain tag and emits a `ReferenceMaterializationWarning`
  (`orcapod.core.referential_tags.reference_materialization = "silent"` hides it).
- A function output named like a tag of its input is an error when the pipeline is built.

### Known limitations

- `Batch`, `MergeJoin`, operator-node result storage, `DerivedSource` over a referential
  stream and saving a pipeline or job raise "not supported with referential tags yet".
  `PollingSource` keeps its tags plain. The identities of referential streams may still
  change.
