### Changed

- Orcapod now requires deltalake 1.6.6 or newer (was 1.0.2). A commit to a Delta table is
  faster with it: a one-row MERGE into a 10-million-row table took about 110 ms instead
  of about 380 ms, and into a 5 GB table about 1.2 s instead of about 2.6 s. Tables written
  by either version are read and appended to by the other, with identical rows, for every
  stored table kind. New tables keep Delta protocol 1/2, with no table features. deltalake
  1.6 no longer logs `Skipping column ... because it's a binary field`.
- `DeltaTableDatabase` refuses two columns, or two fields of one struct, whose names
  differ only in case (`a` and `A`), before anything is queued
  (`UnstorableColumnError`, or `InputValidationError` for a column added beside a held or
  queued one). Delta column names are case-insensitive, and deltalake 1.5.1 and later
  refuses such a table. The in-memory and connector databases still hold such names as
  two columns.
- `DeltaTableDatabase` refuses an append that would change a stored column's recorded
  Arrow type (`InputValidationError` naming the column, before anything is queued). This
  covers a field added to a struct whose type is recorded: every list and map column,
  and every struct holding an unsigned integer, a non-microsecond time type, `float16`
  or a fixed-size type. It also covers another logical type over a stored logical
  column's storage type. deltalake 1.5 and later does not let a commit change a column's
  field metadata, and the record is field metadata. A struct column without a record
  still gains fields, a field may still be omitted or reordered, and a new column may
  still be added. No job reaches the refusal on the tables Orcapod's own nodes write: a
  changed column type changes the table's path.
