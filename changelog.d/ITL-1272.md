### Breaking changes and migration

- `ListSource` has the identity of every other root source: class name, output schema,
  `source_id` and key columns (ITL-1272). Its elements and its tag function enter its
  content hash only through its default `source_id` (the hash of its table), so a
  `ListSource` given a `source_id` is an address like any other source: changing or
  reordering its elements no longer changes its content hash while its output schema stays
  the same (the schema is part of the identity, so elements of another type, or tags of
  another type, still change it), and two `ListSource`s with
  the same elements but different `source_id`s no longer share one. Every `ListSource`'s
  content hash changed, and with it the identity of every node over one. A review of
  every built-in source's identity is ITL-1311.
- `ListSource` no longer takes `tag_function_hash_mode`: the tag function's identity has
  no role left. Remove the argument. It was never written to a saved job.

### Added

- `hash_in_key_order` (keyword-only, default `False`) on `ArrowTableSource`,
  `DictSource`, `DataFrameSource` and `ListSource` (ITL-1272): a source with key columns
  (`record_id_columns`) and no `source_id` hashes its table, for its default source id,
  with the rows sorted by the key columns in the order given, so the same rows in any
  order give one default source id and one content hash. The rows are presented in the
  order given. Refused without key columns and with a `source_id`. Without it, nothing
  changes: the table is hashed as given.
