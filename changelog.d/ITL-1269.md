### Breaking changes and migration

- `AddTags` (`stream.add_tags(...)`) is the same operator for every order of its tags
  (ITL-1269; developer, November 18, 2026: "I absolutely agree to make it entry order
  independent"). The new tags are a set. The operator holds them in name order and places them
  after the input's tags in name order. Its identity and saved config list them that way.
  `add_tags(run=3, cohort="A")` and `add_tags(cohort="A", run=3)` now have one content hash,
  one pipeline hash and one stored path. Before, the keyword order was part of the identity
  and decided the column order. An `AddTags` whose tags were not given in name order gets a
  new identity, so the stored path of its node and every node downstream of it moves.
