### Changed

- **Rows of a stream are built without normalizing each one again** — `iter_data()` of a
  stream over a table (every source, every operator result, every job node's rows) built
  each row's `Tag` and `Data` from a one-row slice through their constructors, which
  normalized the row's types three times (tag, data, source info) and split its columns into
  groups again, although the stream's table is already normalized: 180,000 normalizations for
  60,000 rows. The table is now prepared once for all of its rows, however it is chunked (a
  table a job node builds from rows has one chunk per row), by `Tag.rows_of(table)` and
  `Data.rows_of(table)`, which yield for each row the datagram the constructor builds from
  that row: the same values, system tags, source info, meta values, Arrow types and hashes.
  Building the rows of a 60,000-row source takes 1.5 s instead of 5.0 s, and a job of three
  operator nodes over two 30,000-row sources runs in 17.0 s instead of 24.6 s. No hash,
  stored table or output changes. (ITL-1348)
