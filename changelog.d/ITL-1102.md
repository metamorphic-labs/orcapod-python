### Added

- A run checks its sources for new data first (developer, November 14, 2026; ITL-1102). `job.run()`, `job.run_async()` and a job node's `run()` (a load-only run too) call `check_for_new_data()` once on every source feeding them before deciding which nodes to run. A source that finds new data takes it in and moves its modified time, so the nodes below it run again and compute only the inputs without a stored result; a source that finds nothing moves nothing, so a job whose sources are unchanged computes nothing. `head()` and the notebook preview never check. In-memory sources (`ArrowTableSource`, `DictSource`, `ListSource`, `DataFrameSource`) cannot change and do nothing; a `PollingSource` polls once. `RootSource.check_for_new_data()` is the hook a source class overrides.
- A check that raises does not fail the run: one `SourceCheckFailedWarning` (new, in `orcapod.errors`) per source names the source and the error, the source keeps its data and modified time, the run proceeds with the data the source already holds, and `RunSummary.unchecked_sources` lists the source ("sources not checked for new data (see the warning): ..."). A later failure to read the source raises as before.

### Fixed

- A `PollingSource` moves its modified time only when a fetch returned rows, and to the moment it found them. Before, a fetch that returned no rows also moved it, and a cursor's `modified_at` was used as the time: rows written before a downstream node's last run but fetched after it left that node current, so they were never processed. `Cursor.modified_at` is now informational.
