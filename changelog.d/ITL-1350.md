### Changed

- A `SpiralDBTableSource` looks its table up once when it is built and once per new-data
  check (ITL-1350). Every lookup of a table by name is a round trip to SpiralDB; the
  source used to look the table up for each item it needed (key, id, schema and
  version: four lookups to build, three per check). `SpiralDBConnector.lookup_table`
  returns the table once, with its id and key columns, and reads its schema and version
  when asked, in the same order and under the same conditions as before, so a check
  still finds a table dropped and created again since. Measured on a live project:
  building a source about 1.5 s -> 0.9 s, a check about 1.2 s -> 0.8 s. The connector's
  other methods are unchanged.
