### Breaking changes and migration

- Column names that begin with `_` are reserved. Sources refuse these columns instead
  of silently dropping them. Rename your own columns or drop reserved columns before
  building the source. When reading a table that Orcapod wrote, drop its system columns
  first. The `system_tag_columns` option retains its existing validation.
- Operator output and rename targets and function pod output keys must use names that
  do not begin with `_`. A saved configuration with a reserved function pod output key
  is refused when the pod is rebuilt, including when the original callable is
  unavailable and loading would normally use a proxy. Rename the output key and update
  its downstream references in the pipeline before saving a new configuration.
- Named Python row inputs to `DataFrameSource` and `PollingSource` need the same
  field names in every non-null row. Typed rows of the same kind need the same
  field layout. For sparse mappings, include missing keys with `None` where
  appropriate. If a Pydantic model exposes fields that conversion would drop or
  rename, pass mappings with the intended column names.

### Fixed

- `Pick` and `Index` reject reserved `out` names at construction, so their output
  columns stay visible in stream tables.
- Stored function results refuse reserved user output keys before a cache lookup,
  job replay or provenance read can reconstruct a row.
- Operator caches and cached sources refuse stored user columns in the reserved
  namespace before presenting their rows.
- Raw Arrow and polling sources report reserved column names before validating
  their Arrow types.
- Frame and polling sources report reserved raw names before frame conversion, and
  list sources check names in callback tags before projecting their fields.
