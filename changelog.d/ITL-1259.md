### Breaking changes and migration

- The Python function type is `python.function.v1`, and every stored table's layout marker
  starts at `v1` (`pdb_v1`, `rdb_v1`, `tdb_v1`, `odb_v1`, `sdb_v1`): the first release's
  names (ITL-1259). Every function pod has a new identity and its results are computed once
  again. A saved job that names `python.function.v0` no longer loads its function.

### Added

- A data function type declares what a function of the type means and what its result
  table stores (`orcapod.core.data_function_types`, `PYTHON_FUNCTION`; ITL-1259). A function
  result table is at `.../python.function.v1/rev1/rdb_v1`: the type and its major (in the
  identity), the revision of the type's record and the layout of the common columns (both in
  the path only). Each released declaration is pinned as a snapshot. See
  `docs/reference/data-function-types.md`.

### Changed

- Stores written by Orcapod before 0.4 are no longer looked for: no old layout names, no
  layout-less paths, no job-wide total of old tables (ITL-1259; nobody has such a store).
  A node still reports, and a side-effecting node still refuses, tables of another layout
  under its own name, and rows of another data context.
