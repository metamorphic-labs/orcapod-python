### Breaking changes and migration

- **`GroupBy` refuses a tag whose type holds a struct or a map** (a user class, a
  `dict[K, V]`), as a key and as a non-key tag, with `InputValidationError`: every non-key
  tag orders a group's members, and a struct has no order. Before, such a tag raised a bare
  `TypeError` while grouping, except when no group had two members. Drop the tag before
  grouping (`select_tag_columns`); `GroupBy` drops a non-key tag anyway. (ITL-1250)

### Fixed

- **`GroupBy` groups, orders and emits by Arrow value, never by Python value.** It decides
  which rows form a group and in what order with Polars, and builds its output from the
  input's Arrow columns. Keys that differ only below what Python keeps are now separate
  groups (`time64[ns]` values of 1 ns and 2 ns were one group emitting 0 ns; two `date64`
  values on one day were one group at midnight), and members are ordered by such tags
  exactly. The data lists hold the members' values bit for bit: before, a `time64[ns]` value
  lost its nanoseconds, a `date64` value its time of day, and a float32 signaling NaN came
  back quiet (ITL-1248). Results change only for inputs holding such values; no golden
  value moves. `GroupBy` is also 5 to 8 times faster on 1e6 rows. (ITL-1250)
