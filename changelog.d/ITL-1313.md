### Breaking changes and migration

- `DerivedSource(origin, tags_as_data=...)` and `node.as_source(tags_as_data=...)` need a
  `source_id` (ITL-1313): there is no default any more, and building one without it raises
  `ValueError` before the origin is read. The default it had, `tags_as_data:<label>:<hex>`
  of a hash of the derivation, was of questionable stability (`record_id_columns=None` and
  `record_id_columns=()`, one key policy, gave two ids). Pass `source_id="<a name>"`;
  `as_source` takes it as a keyword. A saved config already stores the source id; one
  without it is refused when loaded. With a given `source_id` the origin enters the source's
  identity only through its schema, as for every named source. Plain `DerivedSource(node)`
  and `node.as_source()` keep their `derived:<label>:<hex>` default.

### Known limitations

- `PollingSource` is provisional in data context v1 (ITL-1314): its default source id and
  its content hash are not frozen and may change in a later release (ITL-1316), and with
  them the system tags, stored paths and record ids of its rows and of every step
  downstream. Building one issues `ProvisionalHashWarning` once per process
  (`orcapod.sources.PROVISIONAL_SOURCES` lists it). It behaves as before otherwise, and no
  golden value pins it.
