### Added

- **Data types per database:** a new reference page,
  `docs/reference/database-types.md`, lists every Arrow type
  (integers of every width, floats, decimals, dates, times, timestamps of every unit and
  zone, durations, text and binary, lists, fixed-size lists, structs, maps, nullability,
  every Orcapod logical type and the library value types) for every database (in-memory,
  Delta Lake, SQLite, PostgreSQL, SpiralDB): kept, kept through a recorded type, or
  refused. It is generated from a test that writes and reads each type through each
  database, and that fails if any database gives a column back other than exactly (type
  with every nested field's name, nullability and metadata, and values bit for bit)
  without an error. (ITL-1334)
- **`DeltaTableDatabase` keeps more types:** `float16` (written as `float32`, which holds
  every `float16` exactly), fixed-size lists, also nested and with null rows (written as a
  `large_list`; a fixed-size list used to read back as a `large_list`, and with a null row
  could not be read back at all), fixed-size binary (read back as `large_binary` before)
  every list (its item was renamed `element` and lost its metadata) and every map (it lost
  `keys_sorted`), all through the recorded-type mechanism already used for unsigned
  integers and nanosecond timestamps.
  A restore never pads, cuts or rounds: stored rows that cannot be what was written raise,
  naming the column. (ITL-1275, ITL-1283, ITL-1334)

### Changed

- **`DeltaTableDatabase` refuses what Delta cannot hold, naming the column:** a
  `decimal256` or an interval column (as Delta's own writer decides), a map whose key or
  item field is not named `key` / `value`, and a new column or nested field holding only
  nulls with no type, raise `UnstorableColumnError` when added, before anything is
  buffered, and a job refuses such a column up front (`require_storable`). They used to
  fail the flush with an error that named no column. A `null`-typed value where the table
  already stores a type is still kept. (ITL-1334)
- **The SQLite and PostgreSQL connectors read a non-null column back non-null:** the
  column is created `NOT NULL`, and a read that projects the table's columns directly now
  gives the field that flag; it read back nullable before. Any other query (a join, an
  aggregate) reads every column nullable. (ITL-1276)
- **`SQLiteConnector` refuses a `double` column holding a NaN or `-0.0`:** SQLite reads a
  NaN back as NULL and `-0.0` as `0.0`. (ITL-1334)
- **`SpiralDBConnector` refuses a logical (extension) type:** `File`, `Directory`,
  `Path`, `UPath`, `UUID`, `list[T]` and `set[T]` of them, user classes and the library
  value types read back from SpiralDB as their plain storage type (SpiralDB drops the
  field metadata that names them). They are refused with `UnstorableColumnError` before
  anything is written, as is a map whose key or item field is not named `key` / `value`.
  (ITL-1334)

- **An append whose field attributes differ from the held column is refused, by every
  database:** a table holds one type per column, so rows appended with other field
  metadata (the column's own, or a struct child's, a list item's, a map key's or item's),
  another nested field name or another `keys_sorted` than the stored rows or a pending
  batch raise `InputValidationError` naming the column and the field, before anything is
  buffered. `InMemoryArrowDatabase` used to give the appended rows the first batch's
  metadata, the SpiralDB connector gave every row the latest batch's, and Delta kept the
  stored metadata, whether or not the column's type was recorded. Nullability is left to
  each database's own rule. (ITL-1334)
- **What a `DeltaTableDatabase` flush would refuse is refused when the rows are added:**
  before anything is buffered, `add_records` checks the rows against the stored table and
  raises `InputValidationError` naming the column and the field. The rows are refused
  when they would:
  - add a non-nullable struct field (the stored rows have no value for it, and Delta could
    not read the table back), or add a struct field inside a map (Delta's merge cannot);
  - omit a struct field or a column stored as non-nullable, or hold a null in such a
    column;
  - give a column another type than the stored one, a `float16` into a `float32` column
    included.

  These used to fail the flush and stay queued, so every later flush failed again. The
  flush repeats the check against the version it loads, since another writer may commit
  in between; rows it refuses are dropped from the queue, and the error says so. A nested
  field an append makes nullable reads back nullable. (ITL-1334)
- **`DeltaTableDatabase` refuses a struct with no fields at any depth:** a Parquet file
  stores values in leaf columns only, so the flush failed. (ITL-1334)
- **`SpiralDBConnector` refuses field metadata below a map, and Arrow's canonical extension
  types:** its metadata record does not descend into a map, so metadata on a map's key or
  item, or inside them, read back dropped. A `uuid` or `json` column (Arrow's own extension
  types) read back as its storage type. (ITL-1334)
- **`UnstorableColumnError` suggests only `InMemoryArrowDatabase`:** it suggested
  `DeltaTableDatabase` for types Delta refuses too (`decimal256`). The message now points
  to `docs/reference/database-types.md` for what each database keeps. (ITL-1334)

### Fixed

- **A fixed-size list with non-null items and a null row can be appended to on Delta:**
  the null row's hidden items reached Delta's writer, which panicked; a null row is now
  written as an empty list. (ITL-1334)
- **An append to a Delta table that evolves a struct keeps every value under its name:**
  Delta's MERGE matches struct fields by position, so rows appended with the fields in
  another order stored each value under another field's name. The rows are now given the
  stored layout by name first (an omitted field reads as null, an omitted non-nullable
  field is refused), and a recorded column's record describes the merged column.
  (ITL-1334)

- **A `null`-typed part of a Delta append is written as typed nulls:** a `null` child of a
  struct that also gained a field made Delta's MERGE panic. A `null` part needs a type at
  its path from either the stored table or a pending batch. (ITL-1334)
- **A Delta append of rows sliced from a larger table writes:** a null list or map row
  at a nonzero slice offset failed the flush ("Null bitmap with offsets slice not
  supported") and stayed pending; every list and map Delta rebuilds now rebases its
  offsets. (ITL-1334)
- **An append that adds a column to a Delta table keeps the other columns' types:** the
  MERGE it goes through wrote each list column's field metadata from the rows, without
  the recorded type or a logical column's extension name, so afterwards a list read back
  with its item named `element`, and a logical list (`set[int]`, `list[Path]`) as its
  plain storage type. (ITL-1334)
- **`SpiralDBConnector` reads back a fixed-size list with non-null items and a null row:**
  the read cast every column to the restored schema, and pyarrow refuses that cast when a
  null row hides null item slots; only columns whose type changes are cast now.
  (ITL-1334)
