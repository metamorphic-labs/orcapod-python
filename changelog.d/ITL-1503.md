### Changed

- A function node in ephemeral mode asks the persistent result store before the ephemeral one: a row that has no pipeline record, but whose input the persistent store holds a result for, now gets that result (recorded as persistent, not computed) where the function ran again before. A fresh result is still saved to the ephemeral store only, and nothing is saved to the persistent store in ephemeral mode.
- A result table gets one result per input: a computation that finds a result already stored for its input, when it is about to store its own, discards its own and uses the stored one. That row is reported as a cache hit. Within one process this holds for every database; a writer in another process is not covered.

### Fixed

- Equal inputs computed at the same moment on the async path stored one result each, and a read of the node gave the last of them for every such row. One result is stored, every row delivers it, and a read gives what was delivered.
