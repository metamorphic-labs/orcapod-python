### Breaking changes and migration

- Source slots take their names from source labels rather than dataset IDs. An
  unlabelled source defaults to its class name. Use the slot label as the key in
  `job.bind(sources=...)`, `job.nodes`, and `job.sources`. Newly saved jobs
  record these slot names. Existing coherent job files keep their recorded names.
- Distinct inputs with the same slot label are refused. Assign a label or use
  `source.as_slot("role")` to give the input a unique name.

### Known limitations

- A job refuses two slots that would hold the same live source identity
  (ITL-1559). Jobs already saved with shared bindings can still be loaded, saved,
  and inspected directly. Running them, including in load-only mode, requires
  distinct bindings.
- A graph's slot labels are captured when its steps are recorded. To change one,
  rebuild the graph (ITL-1559).
- Capture a computation inside its job or use `node.as_source()` to read another
  job's stored results. A prebuilt non-source stream cannot be captured as a
  job input (ITL-1559).
