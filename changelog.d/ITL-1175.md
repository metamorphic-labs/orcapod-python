### Added

- `TagBy` and the stream method `tag_by` give existing data columns the tag role, as
  referential tags (ITL-1175): `stream.tag_by("x", "y")` (or `tag_by(["x", "y"])`). Each
  named column becomes one column in both roles, with its values and source info
  unchanged; the new tags follow the stream's tags in the order given, and that order is
  part of the operator's identity. System tags, record ids and every data column are
  unchanged. A column a function computed may become a tag and then key a join or a
  group. Refused, naming the column: a name that is not a data column of the input, a
  name that is already a tag, a reserved name, and a type that cannot be a tag (a tag is
  one `int`, `float`, `bool`, `str`, `bytes`, `datetime` or `date` value per row; a
  nullable column is refused, with `drop_nulls` as the way out). `TagBy` is registered
  for saved jobs and pipelines.

### Changed

- The error for a name that is a tag in one join input and a data column in the other
  also offers `tag_by` as a way out.
