### Changed

- `GroupBy`, `Batch` and the merged lists of `MergeJoin` gather rows of one data context only
  (ITL-1359): an entry takes its members' one data context, and members of different data
  contexts raise `InputValidationError`, naming the operator, the contexts and one row's tags.
  Nothing is converted between data contexts. Before, a mix was accepted: `GroupBy` and `Batch`
  gave the entry the stream's data context, `MergeJoin` the default one. No golden value
  changes, and no content hash of a result over inputs in the default data context, the only
  one that ships. The content hash of a raw static result of these operators over accepted
  inputs in another data context does move: its table now names that context.

### Known limitations

- The rule does not hold on every path yet (ITL-1359): a job's sync run over source slots in the
  default context accepts a `MergeJoin` mix its async run refuses; entries of different
  contexts in one result lose them in the rows and in a `LOG` table; a uniform default context
  column on a stream in another context is not read as stated; record-batch channels bypass the
  rule. `MergeJoin` fails on an input that already has a column under one of its two temporary
  context names.
