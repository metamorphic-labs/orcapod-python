### Breaking changes and migration

- Delta now refuses raw Arrow columns with extension types in a list item or its
  descendants, directly in a map key or value, or within dictionary values. It
  also refuses nested fields that supply a logical type through
  `ARROW:extension:*` metadata, including unregistered identifiers previously
  accepted. Registering those identifiers could make an identical second write
  fail. An actual nested extension field with its own metadata or in a column
  that needs type recording is also refused. Use plain Arrow storage without
  extension annotations, or use an `InMemoryArrowDatabase` to keep the logical type.

### Fixed

- Delta names the columns with unsupported nested extension types before
  buffering rows. This prevents writes that lose the logical type and lists
  of structs whose renamed item field prevents an identical append. It also
  prevents a sibling such as `uint16` from making a column with a nested extension
  unreadable.
