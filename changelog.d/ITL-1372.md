### Breaking changes and migration

- Delta stores a logical (Arrow extension) type only as a whole top-level
  column. It refuses nested extensions and fields carrying Arrow extension
  metadata within another type, including within a top-level extension's
  own storage. The refusal applies whether or not the logical type is
  registered and also covers some previously accepted struct layouts.
  Use the corresponding Orcapod container or class type to keep the logical
  type: it stores its children as Arrow storage inside one top-level logical
  column. Alternatively, use plain Arrow storage without extension annotations
  or keep the raw Arrow column in an `InMemoryArrowDatabase`.

### Fixed

- Delta names affected columns and their nested paths before buffering rows.
  This prevents nested logical type loss, unreadable tables, and identical
  appends that fail after an apparently successful first write.
