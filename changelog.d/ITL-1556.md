### Added

- **A run reports the observer events it could not record** — `RunSummary` has a new
  attribute, `lost_observer_events`: per observer kind (`"status"` for a `StatusObserver`,
  `"logging"` for a `LoggingObserver`), a `LostObserverEvents` (exported from
  `orcapod.pipeline`) with the number of events that were not written and the first error's
  text; it is empty when every event was recorded. The summary's text and notebook display
  show it as one line. A run with lost events issues one new warning,
  `ObserverEventsLostWarning` (`orcapod.errors`), at the end of the run, at the line that
  started it. (ITL-1556)

### Fixed

- **A failed observer write is no longer silent** — when a `StatusObserver` or a
  `LoggingObserver` could not write an event to its database (a store that refuses the
  rows, or one that fails partway through a run), the observer logged the error and the job
  finished as if nothing had happened: nothing in the result or the summary said that the
  status and log records were incomplete. The run still continues and its results, its
  other summary counts and its exit are unchanged, and each failed write is still logged
  with its traceback; the loss is now counted in `RunSummary.lost_observer_events` and
  reported by one `ObserverEventsLostWarning` per run, on the sync and the async
  orchestrator, for `job.run()`, `job.run_async()` and load-only runs, and for the
  observers inside a `CompositeObserver`. A job node's own `run()` takes no observer, so
  its summary lists none. (ITL-1556)
