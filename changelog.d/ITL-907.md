### Breaking changes and migration

- A source refuses a dict column that holds one key twice in a cell, when it is built
  (`RepeatedDictKeyError`, an `InputValidationError`, naming the column and the key). To
  Orcapod every Arrow list of `struct<key, value>` is a `dict[K, V]`, so this applies to
  any such column of a table built outside Orcapod, at any depth. Remove the repeated
  entries before building the source, or, if the column is meant as a list of pairs, give
  the struct's fields other names. Dicts Orcapod builds from Python values never repeat a
  key and are not affected; no stored value, path or hash changes (ITL-907).

### Fixed

- A stored dict with a repeated key is no longer read as a Python `dict` that silently lost
  an entry. `as_dict()`, `iter_data()` and a function pod taking the column raise
  `RepeatedDictKeyError`, also for a stream built from an Arrow table of your own, which
  is not scanned when it is built. Two keys are the same key exactly when a Python `dict`
  would keep one of them: `0.0` and `-0.0` are, two nulls are, two NaN keys are not
  (ITL-907).
