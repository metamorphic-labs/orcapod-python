### Fixed

- **A loaded operator node looks for its stored rows under the path its run wrote.** An
  operator node of a job loaded with `PipelineJob.load` recomputed its pipeline hash from
  inputs rebuilt from the saved schemas, which do not keep a column's nullability. With a
  nullable tag or data column (the default for a table built with `pa.table` or from
  pandas) it looked under another table path and reported "the cache table is absent". It
  now takes the pipeline hash saved with the job, the run's. No hash or stored path of a
  running job changes. (ITL-1043)
- **A loaded operator node in `CacheMode.REPLAY` no longer shows stored rows as none.** When
  its cache table holds rows but none carries the node's content hash (a job whose
  in-memory input sources were not saved cannot reproduce the content hash its run stored
  them under), `as_table()`, `iter_data()` and `head()` raise a `RuntimeError` saying how
  many rows are stored and how to read them, instead of returning zero rows. (ITL-1043)
