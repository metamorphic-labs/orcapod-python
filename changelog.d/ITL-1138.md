### Fixed

- A job over a column of a user class (an ordinary dataclass, an `orcapod.dataclass` or a pydantic model) loaded with `PipelineJob.load` in a process where nothing has registered the class yet reads like the job that saved it (ITL-1138). The load cannot restore such a column's saved type to a class, so the source slot held the saved type text: its pipeline hash was the hash of that text, and binding the same source was refused ("data column 'p' is declared extension<…> but the source has A") unless the class had been registered before the load. A loaded source slot now keeps its saved pipeline hash, and its saved content hash while no source is bound, as loaded function and operator nodes keep theirs, and restores such a column's type when a source is bound (building the source registers the class). Every node then has the saving process's hashes, schemas, system-tag column names and stored rows, and `run(load_only=True)` finds every stored result. A slot whose class is still not registered at bind refuses the source with an error that names the column and the saved class and says how to register it. No hash, golden value or stored table changes; the job file format is unchanged, and a file without a slot's saved hashes still loads.
