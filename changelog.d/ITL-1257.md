### Breaking changes and migration

- A function with no `output_keys` that returns a value other than `None` raises
  `NoOutputsDeclaredError` (an `OutputTypeError`) instead of having the value dropped
  (ITL-1257). To keep the value, declare an output key with its type (a return
  annotation or `output_schema`); otherwise return nothing.

### Fixed

- A function annotated `-> None` with no `output_keys` is accepted as a function with no
  outputs, like a function with no return annotation (ITL-1257). It was refused ("has a
  return type annotation, but no return keys were specified") because `typing.get_type_hints`
  reads `-> None` as `NoneType`. `-> None` with `output_keys` is now refused when the pod is
  created; it was accepted and gave an output column of type `NoneType`.
- A function with a positional-only parameter is refused when the pod is created, naming
  the parameter (ITL-1258). A pod passes its inputs by name, so a call that supplied
  such a parameter failed with a `TypeError` (one with a default worked only while the
  input never held it, and the parameter could never be given).
