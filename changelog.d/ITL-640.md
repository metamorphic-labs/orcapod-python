### Breaking changes and migration

- **A schema is hashed as its Arrow schema, everywhere a schema enters an identity** (ITL-640,
  ITL-949). A source's pipeline hash and content hash, an input slot's, the system-tag column
  names and the output-schema part of a function's `uri` are now built from Arrow types
  (`StarfixArrowHasher.hash_schema`, label `arrow_schema_v1`), no longer from Python types. Two
  sources whose columns differ only in an Arrow type (`int32` and `int64`, `int8` and `uint8`,
  timestamp unit or zone, decimal precision, `date32` and `date64`, list item nullability, a
  struct field's type, `fixed_size_list` and `list`) now have different pipeline hashes, stored
  paths and system-tag names, so they no longer write into one table. Column order, large and
  non-large variants, a list's item field name, dictionary encoding and field metadata are not
  part of it. Every pipeline hash, stored table path, system-tag column name and function `uri`
  moves; stores written by earlier versions are not read. `output_schema()` still reports
  Python types.
- **Binding compares Arrow types.** A source bound to a slot must have the slot's Arrow types; the
  only difference accepted is a non-null column where the slot's is nullable. A slot made from a
  source keeps that source's Arrow types. A slot declared with Python types means one Arrow type
  per Python type (`int` is `int64`, `datetime` is `timestamp[us, tz=UTC]`), so a source of
  another width, unit or zone is refused; declare such a slot with Arrow schemas:
  `SourceNode(name, tag_schema=pa.schema([...]), data_schema=pa.schema([...]))`.
- **A `PollingSource` refuses a fetched batch whose Arrow types differ from its declared
  schema** (`SchemaInconsistencyError`, before the batch is committed). `impl.schema()` may now
  return a `pa.Schema`, which is then the source's schema exactly.
- **Saved job files hold each input slot's and each node's own Arrow types** (nested
  nullability, units, zones, decimal precision, fixed-size widths and logical type identifiers
  included), and a load rebuilds them; before, the types were re-derived from Python types, so
  a type with no Python counterpart (`time64[ns]`, `duration[ns]`, `decimal128(38, 10)`,
  `fixed_size_binary(3)`) was saved as `null`. One writer writes a slot's `source_config` and
  every node's `output_schema`; the format version is unchanged (same keys, more exact text).
  A logical type's identifier is written whether the field carries it as a live extension
  type or as `ARROW:extension:*` field metadata (a table read back from a store), at any
  depth.
  A file written before keeps its text: a node whose saved type is `null` still loads, and
  `node.as_source()` over it, which checks stored reads against the node's types, raises
  naming the column. A dictionary-encoded column is saved as its value type.
- **A logical type is one schema identity in every Arrow representation.** A field that
  carries its identifier as `ARROW:extension:*` metadata (the IPC form of a table read back
  from a store, or a process where pyarrow has not registered the type) is brought to the
  live extension type before it is hashed, saved or declared
  (`logical_types.canonical_form.canonical_logical_schema`), so `File`, `list[File]`, `Path`
  and every other logical type hash, save and declare alike in both forms. A schema declared
  in Arrow with such a field (a `SourceNode`, a `PollingSource`'s `impl.schema()`) declares
  that logical type.
- **A slot declaring a column with no Arrow type is refused when it is declared** (`ValueError`
  naming the slot and each such column, for example `x: int | str | None`): a slot's identity
  is its Arrow schema. Before, it was refused only when a source was bound.
- The function `uri`'s output-schema component is the semantic hash of the Arrow schema hash
  of the declared outputs, as the system-tag column names are the semantic hash of the source's
  tag and data schema hashes: a 64-character hex digest in each case.

### Changed

- `node.as_source()` (`DerivedSource`) has the Arrow types of its origin's rows before and after
  rows are stored, so its identity does not change when the origin runs (ITL-1280: before a
  run it widened `int8`/`int32`/`uint16` to `int64` and `float16`/`float32` to `double`, gave
  a timestamp of any unit or zone `timestamp[us, tz=UTC]`, and raised on a decimal); a stored read whose
  type differs from the origin's (Delta reads a `fixed_size_list` back as `large_list`,
  ITL-1275) is refused, naming the column and both types.
- An unbound input slot that knows its Arrow types (made from a source, or loaded from a saved
  job) gives its typed zero-row table from them, so a loaded job's nodes have the stored types
  before any source is bound; a loaded function node types its output from its saved types.
- A logical type a data context cannot read, in a schema, is reported with its column name.

### Known limitations

- The type converter writes `list[int]` and `list[int | None]` as one Arrow type (a nullable
  item), so two functions that differ only in that declaration share the output-schema part of
  their `uri` (ITL-1136).
- The SQLite connector database reads a non-null column back as nullable (ITL-1276).
