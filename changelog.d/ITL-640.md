### Breaking changes and migration

- **A schema is hashed as its Arrow schema, everywhere a schema enters an identity** (ITL-640,
  ITL-949). A source's pipeline hash and content hash, an input slot's, the system-tag column
  names and the output-schema part of a function's `uri` are now built from Arrow types
  (`StarfixArrowHasher.hash_schema`, label `arrow_schema_v1`), no longer from Python types. Two
  sources whose columns differ only in an Arrow type (`int32` and `int64`, `int8` and `uint8`,
  timestamp unit or zone, decimal precision, `date32` and `date64`, list item nullability, a
  struct field's type, `fixed_size_list` and `list`) now have different pipeline hashes, stored
  paths and system-tag names, so they no longer write into one table. Column order, large and
  non-large variants, a list's item field name, dictionary encoding and field metadata are not
  part of it. Every pipeline hash, stored table path, system-tag column name and function `uri`
  moves; stores written by earlier versions are not read. `output_schema()` still reports
  Python types.
- **Binding compares Arrow types.** A source bound to a slot must have the slot's Arrow types; the
  only difference accepted is a non-null column where the slot's is nullable. A slot made from a
  source keeps that source's Arrow types. A slot declared with Python types means one Arrow type
  per Python type (`int` is `int64`, `datetime` is `timestamp[us, tz=UTC]`), so a source of
  another width, unit or zone is refused; declare such a slot with Arrow schemas:
  `SourceNode(name, tag_schema=pa.schema([...]), data_schema=pa.schema([...]))`.
- **A `PollingSource` refuses a fetched batch whose Arrow types differ from its declared
  schema** (`SchemaInconsistencyError`, before the batch is committed). `impl.schema()` may now
  return a `pa.Schema`, which is then the source's schema exactly.
- **Saved job files hold each input slot's and each node's own Arrow types** (nested
  nullability, units, zones, decimal precision, fixed-size widths and logical type identifiers
  included), and a load rebuilds them; before, the types were re-derived from Python types, so
  a type with no Python counterpart (`time64[ns]`, `duration[ns]`, `decimal128(38, 10)`,
  `fixed_size_binary(3)`) was saved as `null`. One writer writes a slot's `source_config` and
  every node's `output_schema`.
  A logical type's identifier is written whether the field carries it as a live extension
  type or as `ARROW:extension:*` field metadata (a table read back from a store), at any
  depth. A map is written with its key and item as whole fields
  (`map<key: large_string not null, value: int8 not null, keys_sorted>`), so the item's
  name and nullability survive a save and load. A nested field name is written as it is only
  when it is plain (ASCII letters, digits, `_`, `.` and `-`: `item`, `key`, `value`);
  any other name (a character of the type text, whitespace, a newline, a quote, a
  non-ASCII character, the empty name) is written as a JSON string
  (`struct<"a:b": int8>`) and read back exactly; some such names could not be read back
  before. Saved pipeline and job files are now at format 0.4.0, the only format a load
  reads: a file of an earlier format (0.1.0 to 0.3.0) is refused with a message saying
  so, never read in its old grammar (load and save had not been used in production;
  taking older files to the current format is the migration tool's work, ITL-1048). A
  file without a node's nullability record or without a node's run content hash is
  malformed and refused, naming the record; it is no longer loaded with every column read
  as non-null or with a guessed run hash.
  A dictionary-encoded column is saved as its value type. A `decimal32` or `decimal64`
  column reads back at its own width. Saving refuses, before anything is written and
  naming the node and column, a type whose text would not read back as the same type
  (`month_day_nano_interval`, `string_view` or `binary_view` of a slot declared in
  Arrow), so no saved file is one that cannot be loaded.
- **A schema hash is the hash of the declared schema** (developer decision, November 21,
  2026). Every logical type is hashed as its storage type with its identifier
  (`ARROW:extension:name` and `ARROW:extension:metadata`) as field metadata, at any depth,
  whether it arrives as a live extension type, in the metadata (IPC) form of a table read
  back from a store, or unregistered in the process. So one logical type has one schema
  hash in every form. Before, a type whose values a value handler hashes (`File`,
  `Directory`, `numpy.ndarray`, torch, pandas, Polars) was hashed as `large_binary`, the form
  `hash_table` uses, and the same `File` field in metadata form had another schema hash.
  `hash_table` is unchanged.
- **A schema declared in Arrow with a logical type in metadata form declares that logical
  type.** A field that carries its identifier as `ARROW:extension:*` metadata at the top of a
  column becomes the live extension type when a `SourceNode` or a `PollingSource`'s
  `impl.schema()` is declared with it, and when a saved schema is read back
  (`logical_types.canonical_form.declaration_form_schema`), so a `Path` field declares `Path`,
  not `str`, and accepts rows of that type. An identifier inside a plain list, struct or map
  stays in the metadata form (Arrow cannot build an empty table of a nested extension type):
  such a slot, a source of the same table and the slot made from that source have one
  schema and one pipeline hash, before and after a save and load.
- **A raw `ArrowTableStream` can no longer hold a union, list-view or run-end-encoded
  column.** A column whose Arrow type is, or contains at any depth, a union (dense or
  sparse), a `list_view`, a `large_list_view` or a run-end-encoded type is refused when the
  stream is built (`InputValidationError` naming each column with its role and type), as a
  source already refused them: a stream's identity is its Arrow schema hash, which cannot
  hold them. Cast a list view to the large list of the same items, expand a run-end-encoded
  column (`pyarrow.compute.run_end_decode`), and split a union into one column per member
  type.
- **An Arrow hasher must implement `hash_schema`.** It is a member of
  `ArrowHasherProtocol`: every schema that enters an identity is hashed by it. A data
  context whose Arrow hasher has no `hash_schema` is refused when the context is built
  (`ContextValidationError`, naming the hasher's class).
- **A `CachedSource` refuses a cache read whose Arrow types are not its source's**
  (`InputValidationError`, naming the column and both types), as `node.as_source()`
  refuses a stored read: a Delta cache gives a `fixed_size_list` column back as
  `large_list` (ITL-1275), so a `CachedSource` of such a column on Delta is refused on
  read instead of presenting rows of another type under the source's identity.
- **A `PollingSource` with a declared schema refuses a fetched batch with a column the
  declaration does not name** (`SchemaInconsistencyError` naming each, before anything
  is committed): the rows' system-tag names would not be the declared identity's.
- **A slot declaring a column with no Arrow type is refused when it is declared** (`ValueError`
  naming the slot and each such column, for example `x: int | str | None`): a slot's identity
  is its Arrow schema. Before, it was refused only when a source was bound.
- The function `uri`'s output-schema component is the semantic hash of the Arrow schema hash
  of the declared outputs, as the system-tag column names are the semantic hash of the source's
  tag and data schema hashes: a 64-character hex digest in each case.

### Changed

- `node.as_source()` (`DerivedSource`) has the Arrow types of its origin's rows before and after
  rows are stored, so its identity does not change when the origin runs (ITL-1280: before a
  run it widened `int8`/`int32`/`uint16` to `int64` and `float16`/`float32` to `double`, gave
  a timestamp of any unit or zone `timestamp[us, tz=UTC]`, and raised on a decimal); a stored read whose
  type differs from the origin's (Delta reads a `fixed_size_list` back as `large_list`,
  ITL-1275) is refused, naming the column and both types.
- An unbound input slot that knows its Arrow types (made from a source, or loaded from a saved
  job) gives its typed zero-row table from them, so a loaded job's nodes have the stored types
  before any source is bound; a loaded function node types its output from its saved types.
- A logical type a data context cannot read, in a schema, is reported with its column name.

### Known limitations

- The type converter writes `list[int]` and `list[int | None]` as one Arrow type (a nullable
  item), so two functions that differ only in that declaration share the output-schema part of
  their `uri` (ITL-1136).
- The SQLite connector database reads a non-null column back as nullable (ITL-1276).
