### Breaking changes and migration

- SpiralDB is read through `spiral-sdk` (the `spiraldb` extra pins `spiral-sdk==0.16.74`), and `pyspiral` is gone. Both packages provide a module named `spiral`: install into an environment without `pyspiral`.
- Orcapod only reads SpiralDB for now. Every write of `SpiralDBConnector` (`create_table_if_not_exists`, `upsert_records`, `delete_table`) and every job whose database is on one raises `SpiralDBWriteNotSupportedError`, before anything is buffered or run. Writing is a follow-up of ITL-1186.
- A table's non-nullable columns and Arrow metadata are read from its dataset's schema table, `__orcapod_schemas__`, not from the table's metadata. Datasets written by an earlier release must be migrated once with `scripts/migrate_spiral_schemas.py` (`RELEASING.md`); then schemas, hashes and source ids are as before. Until then their tables read with every column nullable, with `UnrecordedTableSchemaWarning`, and their hashes differ.
- `read_nullability_record` and `write_nullability_record` are removed, and `NullabilityRecordError` is replaced by `TableSchemaError`.
- Row counts are counted from the keys: `row_count_estimate` is exact and reads every key, the `max_rows` check reads at most `max_rows + 1` keys, and a preview of more than 100,000 rows shows no total.
- `overrides` takes `server.url` only; other keys are refused. `~/.spiral.toml` is not read.
- A pinned version (`asof=`) whose columns differ from the table's recorded schema is refused.

### Added

- `scripts/migrate_spiral_schemas.py`: the one-time migration of a dataset's schemas (dry run, write, verify).
- `SpiralDBSignInError`: raised when no SpiralDB sign-in is found, instead of starting one.
- `TableSchemaError` and `UnrecordedTableSchemaWarning` for a table whose recorded schema is missing, incomplete or disagrees with it.

### Changed

- A `where` condition on a `uint64` column, which `pyspiral` could not compare, is answered.

### Known limitations

- A saved SpiralDB login that has expired is not detected: the client may print a sign-in prompt and wait. Run `uv run spiral login` again.
- A `SpiralDBConnector` cannot be used in a forked process (`spawn` works); it is refused there.
