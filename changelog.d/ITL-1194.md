### Added

- `MergeJoin` handles referential tags (ITL-1194), following `Join`: a tag referential in
  both inputs is one scalar referential column, not a two-element list, and its source
  info is one merged token, the `join_v1` fold of the two inputs' tokens (sorted), as
  `Join` gives. A tag referential in one input stays referential with its own token when
  the other input has it as a plain tag or not at all; a data-only column of that name in
  the other input is refused. A shared key that is `T` in one input and `T | None` in the
  other is `T` in both roles (ITL-829). Every other colliding data column is merged into a
  sorted list, as before; inputs without referential tags merge exactly as before.
