### Fixed

- **A slot bound to a narrower source with one data-tag can be read** — with tags
  declared `j, k`, exactly one of them a data-tag, and a narrower source bound to the
  slot (for example `x: int` into a slot declaring `x: int | None`), the slot's
  `as_table()` and `head()` raised `KeyError` because the data-tag column was placed
  twice and another column lost. They now give each column once. Running the job was not
  affected, and no arrangement that worked changes its column order. The same defect
  made a source with one plain tag and one data-tag, bound in another column order, fail
  when its slot's table was read. (ITL-1420, ITL-1245)
