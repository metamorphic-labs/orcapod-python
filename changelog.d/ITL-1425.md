### Breaking changes and migration

- Every source id now names the kind and the implementation version of the source that
  reads the data (ITL-1425): it is `<kind>_v<N>:<name>`, where the kind is the source's
  config type key (`csv`, `delta_table`, `sqlite_table`, `arrow_table`, ...) and `N` the
  version its class declares (`SOURCE_VERSION`, 1 for every kind today). Orcapod always adds
  the kind part: a `source_id` you give is the name and is kept exactly
  (`CSVSource(..., source_id="units").source_id == "csv_v1:units"`), and a default name
  loses its kind prefix (`csv_v1:<path>`, `arrow_table_v1:arrow_v1:<hex>`). The full id is
  what system tags, source-info tokens and `source_id` show; record ids are unchanged and
  never hold the source id. Code that compares a source id with the string it gave compares
  `source.source_name` instead.
- The class name is no longer part of a source's content hash: a root source is identified
  by its source id, its Arrow schema and its key columns. Content hashes of every source and
  of everything downstream of one change, and so do stored pipeline rows, cache tables of
  `CachedSource` and default ids of `node.as_source()`. Stores written before this change
  are not migrated.
- A job slot (a `job.nodes` key and a `bind` key) is named by the source's name, not its
  full id, so `job.bind(sources={"units": ...})` is unchanged.
- A saved source config holds `source_name` and `source_version` in place of `source_id`.
  Job files saved before this change are refused on load; save them again. A job saved
  under one version of a kind and loaded where the class declares another rebuilds the
  source as the installed version, with that version's id, and warns
  (`SourceVersionWarning`).
- `CachedSource` no longer takes `source_id`: it presents its wrapped source's id.
- A given name that starts like the id of a source kind (`delta_table_v1:units`) is kept as
  the name, after the reader's own kind part, and warns (`SourceNameWarning`).
- `PollingSource`'s identity now holds its source id, so two polling sources over one
  implementation with different given ids are two sources (provisional, ITL-1316).
