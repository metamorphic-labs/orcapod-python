### Breaking changes and migration

- **`MergeJoin` is ordered, not commutative.** `MergeJoin()(a, b)` and `MergeJoin()(b, a)`
  are two different steps with two identities. Their content hashes differ whenever `a` and
  `b` are different sources, and so do the stored paths of everything downstream; their
  pipeline hashes differ when the inputs' pipeline hashes do (two inputs of one schema have
  one pipeline hash, so the ordered pair is the same either way). A merged column holds, on every row,
  `[value of the first argument, value of the second]`, and its source-info list the two
  tokens in the same order; before, each merged column was sorted on its own values, so the
  lists of one row did not follow the same input. Each input's system-tag columns now end in
  its argument index (`:0`, `:1`) rather than its position in pipeline-hash order. Results
  stored by a `MergeJoin` before this change are computed again. If your pipeline depended
  on sorted lists, sort them in a function pod. (ITL-1281, ITL-1241)

### Changed

- **`storage_sort_key` is removed** from the NumPy array and torch tensor logical types, at
  the developer's request: its one caller was `MergeJoin`'s sort, which is gone. (ITL-1281)

### Fixed

- **`MergeJoin` and `Batch` keep every value exactly.** Both built their lists from Python
  values: a `time64[ns]` value lost its nanoseconds, a `date64` value off midnight came back
  at midnight, a float32 signaling NaN came back quiet, and `MergeJoin` panicked on a
  `decimal256` column. The lists are now built from the inputs' Arrow arrays, so every value
  is the input's, bit for bit, for every Arrow type; `MergeJoin` gives Polars only the
  prepared join keys and row numbers, as `Join` does. `Batch`'s results change only for
  inputs holding such values; no `Batch` golden value moves. Not covered: a data column of
  the Arrow `null` type (or a list of it) keeps that type in the result's table, but read as
  rows or on the async path it follows `Data`'s null convention and is typed
  `large_string` (ITL-1319, as before this change for `Batch`). (ITL-1281)
- **`MergeJoin` merges a colliding column holding nulls or structs.** It raised `TypeError`
  for a null among the merged values (ITL-1243) and for struct values (ITL-839), because it
  compared them; nothing is compared now.
