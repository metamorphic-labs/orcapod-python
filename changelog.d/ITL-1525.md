### Fixed

- A function node no longer logs "These inputs will be recomputed" when it serves a
  stored result (ITL-1525). When an input has several pipeline records and the newest
  one's result is gone, the node serves the result still stored for that input, in full
  and load-only runs, without calling the function; that is ordinary and is no longer
  logged. The warning remains for inputs with persistent records and no matching
  result in either store, and now says what each kind of run does instead of promising
  a recompute. No behaviour changed.
