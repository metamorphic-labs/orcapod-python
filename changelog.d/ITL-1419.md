### Breaking changes and migration

- Reading argument symmetry raises `RepeatedOperandError` (an `InputValidationError`)
  when a flat unordered group collapses repeated inputs. This applies to built-in and
  custom operators, including `Rejoin` and the join used by a function pod. Two inputs
  with the same identity count as repeats. The developer approved the refusal
  on 2026-11-27 as a stopgap until ITL-1511 allows repeats with a unique/repeat toggle.
  Previously `Join()(d)` and `Join()(d, d2)` could share a content hash and cache entry
  despite yielding different rows when `d2` shared `d`'s identity. The error names the
  pod that received the repeated inputs and points to the ordered `MergeJoin()(d, d)`
  for self-joins. An operand whose identity cannot be computed raises its existing
  hashing error in either argument order, even when another input repeats. Overlapping
  data columns still raise an error when the step is built.

### Fixed

- A job runs an ordered operator given one stream for both inputs, `MergeJoin()(a, a)`
  and `SemiJoin()(a, a)` (ITL-1419, stage 1 of ITL-1472). A pipeline's graph edges now
  carry their input position, `(upstream, node, position)`. The position is the argument
  index for an ordered operator, `None` for a commutative one (also with one input), and
  0 for a function or side-effect pod. An operator using a nested ordered group also
  keeps its argument indices. Both orchestrators give a node one input per
  edge, so both inputs reach the operator when it runs in a job made from a `Pipeline`
  or a `PipelineJob`, after `PipelineJob.load` and through `node.run()`. Positions
  exist in memory. A saved file still lists each `(upstream, node)` pair once, and the
  loader reconstructs positions from the operator's saved `inputs` list. When ITL-1511
  allows repeats, identical edges will get occurrence numbers so each edge can be
  identified individually.

### Known limitations

- Standalone row computation such as `Join()(d, d).as_table()` or a function pod's row
  read over several inputs can skip identity formation and proceed. The same invocation
  in a job raises `RepeatedOperandError`. The developer accepted this discrepancy as
  part of the stopgap. ITL-1511 will remove it.
- `diagram()` draws one line for the two inputs of `MergeJoin()(a, a)`. ITL-1530 tracks
  drawing both lines.
- An operator a loaded file keeps read-only (its config cannot be rebuilt) has its inputs
  positioned by argument index, also when it is commutative. Such a node never runs.
  Saved positions are stage 2 of ITL-1472.
