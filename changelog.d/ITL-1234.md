### Changed

- `GroupBy` puts all rows whose key is NaN into one group (ITL-1234), as the joins match a
  NaN key; with several keys, the key tuples compare element by element with that rule.
  Before, each such row was a group of its own, and those groups came out in the input's
  row order. A NaN key sorts after every number and before null. Only two kinds of input
  change: one with a NaN key (its groups, member lists, folded ids and hashes), and one
  with a group whose members mix `0.0` and `-0.0` (its key and hashes; see Fixed). Stored
  rows of such a `GroupBy` and of the nodes after it are not replaced: delete those tables
  or attach a new database before running it with this version (`clear_cache()` clears
  memory only).

### Fixed

- `GroupBy` emits a float key whose members differ in bits as the one with the smallest
  bit pattern at the column's own width (ITL-1234): `0.0` over `-0.0`, a positive NaN over
  a negative one, and a signaling NaN (smaller bits) over the canonical quiet NaN. Before,
  `0.0` and `-0.0` were already one group, but the group emitted the key of the first row
  in input order, so its value and the row's hashes depended on the row order. The key is
  now taken from the input's Arrow column: a `float32` signaling NaN key is emitted with
  its bits (it came back quiet). A logical type stored as a float is chosen by the bits of
  its storage. A group whose members agree emits their value as before.
