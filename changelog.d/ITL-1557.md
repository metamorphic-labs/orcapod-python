### Breaking changes and migration

- Cached sources write nullable source-info fields and new record hashes under
  `sdb_v2`. Older `sdb_v1` tables are reported and left untouched. A bound source
  populates the new cache from its live data.

- Operator caches store and hash the output stream's declared fields under
  `odb_v3`. Older `odb_v2` tables are reported and left untouched. LOG runs
  populate the new table (ITL-1562).
- A bare ArrowTableStream with a formerly required token field has a new content
  hash. Jobs over that stream have new downstream node content hashes and stored
  pipeline record keys. Entry and instance IDs are preserved.
- Jobs fed by an Arrow-backed DataFrameSource without an explicit schema can
  move when a null-free data field was declared nullable, including a data-tag.
  Preserving that declaration changes the source row entry ID, function instance
  and record IDs, and the `pdb_v2` path and key in both execution modes. A
  generated source ID also changes. An explicit source ID and the `rdb_v1` path
  and result key match the previous behavior when the result ID is held fixed.

### Fixed

- Source-info token fields are nullable in streams, rows, and streaming batches,
  including empty outputs.
- DataFrameSource preserves declared Arrow fields and rejects non-text custom
  system-tag columns before applying an explicit schema.
- Adding Python system tags to an Arrow-backed Tag preserves its existing
  system-tag field declarations.
- Record-batch channels refuse token types that disagree with the concrete
  stream. Python replacements on Arrow-backed Data keep the held token type
  and reject values that do not fit.
- DBTableSource validates nominated system-tag fields against the batch schema
  when the connector provides no column information.
