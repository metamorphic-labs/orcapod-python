### Fixed

- **An append of another logical type is refused:** every database (in-memory, Delta Lake,
  and the connector databases, directly and through `ExtensionAwareDatabase`) refuses rows
  whose column, or a field nested in it (a struct child, a list item, a map key or item),
  has the stored or pending column's storage type but another logical type identifier:
  another extension name, the same name with other extension metadata, or a logical type
  where the stored column has none, and the reverse. It raises `InputValidationError`
  naming the column and both identifiers before anything is written, whatever
  `skip_duplicates` (an append of only rows already stored, which wrote nothing and raised
  nothing before, is refused too). Before, such rows were
  accepted in several cases (a Delta column in the annotated form, extension arrays whose
  types differ only in their metadata) and read back as the stored type. An append with
  the same identifier is decided as before; identifiers are compared as stored bytes. A
  list item or map key or item of a stored Delta table, whose identifier Delta does not
  keep (ITL-1372), is decided as before.
  (ITL-1371)
