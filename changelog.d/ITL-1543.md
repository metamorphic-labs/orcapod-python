### Breaking changes and migration

- Sources reject Arrow `null` fields at any depth, including in reserved columns.
  Declare a supported nullable column type for missing values.
- A custom system-tag column on a source must be a non-nullable string column
  with no null values. Sources also reject missing names in `system_tag_columns`.
  Convert custom tags to text before building the source.
- Sources refuse Arrow field metadata on nominated custom system tags, including
  tag copies nominated with `system_tag_columns`. Remove the field metadata before
  building the source. Rebuild a source cache if it was written with field
  metadata on a system tag. ITL-1561 tracks re-evaluating this restriction.

### Fixed

- Join uses the declared fields of inputs tied on pipeline hash to set the
  sorted system tags' nullability. The tag is non-nullable when every
  corresponding input field is non-nullable. Existing entry IDs, instance IDs,
  record IDs and operator hashes for source inputs stay the same.
- Rows preserve the stream's Arrow fields for system tags, including width,
  nullability, and metadata. Standalone async Join uses those fields as well.
  IDs can change for hand-built streams with unusual system-tag fields.
- Standalone async Join preserves the declared Arrow fields of custom system
  tags when carrying them with their IDs on a shared provenance path. Entry-ID
  errors for a raw Arrow Null system tag name the column and ask for a
  supported nullable type.
