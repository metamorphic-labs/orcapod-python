### Breaking changes and migration

- **A stream whose source-info token does not have the shape of its data is refused.** A
  token column's type is some list layers on top of a string, and those layers must be the
  outer list layers of its data column: a `large_list` of tokens needs a `large_list` of
  values, a fixed-size list a fixed-size list of the same size. The values may be deeper
  than their tokens, and a plain string token fits any value. A token that has a list layer
  is never null, though an element inside it may be; a plain string token may be null. The
  rule is checked where a stream is built from a table, and a stream that breaks it raises
  `InputValidationError` naming the token column, its data column and both types. Sources,
  operators and functions always build tokens of the right shape, so only a table built by
  hand with `_source_*` columns is affected. Such a table used to be accepted because
  nothing checked it; downstream, a `Join` over a data-tag with a null list token silently
  stored the characters of an internal marker as the merged token. (ITL-1491)
- **Inputs that declare one token column with two types are refused.** `MergeJoin` (a
  colliding data column) and `Join` (a data-tag both inputs hold, whose tokens the join
  merges) raise `InputValidationError` naming the column and both types, on the sync and the
  async path, whether or not a key matches. Only hand-built raw streams can declare such
  types (a list of tokens in one input and a plain string token in the other, or list items
  that differ in nullability). Such a job used to complete when the tokens' values happened
  to type alike, because both token columns were typed again from their values before the
  operator saw them, which silently changed the declared types. Declare one type in both
  inputs. (ITL-1491)

### Changed

- **The type of a source-info token column is determined by the pipeline, never by the
  tokens' values.** A source builds plain `large_string` tokens, and each operator determines
  its output's token types from its inputs' types, as it does for every other column. A row
  read from a stream keeps that type where it used to be typed again from its value: in the
  table built from rows between two nodes, in a node's output, in a row shown as a table
  (`data.as_table(columns={"source": True})`, and the Python type
  `data.schema(columns={"source": True})` reports), in the rows an async `Join` merges, in
  the element `Index` takes from a list of tokens, in a function pod's stream outside a job,
  and in record batches. For the tokens that sources and operators build, nothing changes:
  no hash, stored path or stored column type moves. A token is still typed from its value
  where it is first created from a Python value and no Arrow type exists
  (`Data(..., source_info=...)`, `with_source_info`). (ITL-1491)
- **A hand-built raw stream keeps the token type it declares.** A fixed-size list of tokens
  (over a fixed-size list of values) stays a fixed-size list, where it used to become a
  `large_list`, and a list of tokens keeps its item field's name, nullability and metadata,
  also in an operator cache. (ITL-1491)
- **A data-tag that falls through a function pod keeps its source-info token with its type
  unchanged.** The token used to be typed again from its value. A column a function returns
  is not affected: its token points to the function. (ITL-1491)

### Fixed

- **Rows with a nested source-info token column behave the same on the sync and the async
  path.** A row whose token column is nested (a list of tokens, or a list of such lists)
  and whose tokens could not be typed again from their values (an empty list, or a null
  inside a list of lists) raised an Arrow type error where the sync path builds a table from
  rows between two nodes, while the async path recorded the rows. Both paths now pass such
  rows on and store them, with the same token types and the same entry, instance and record
  ids. (ITL-1491)
- **An async `Join` writes the token of a merged data-tag with the type its inputs
  declare.** It rebuilt the merged token from its Python value, so a list token that the
  sync path kept as declared became another list type on the async path, and a job run on
  one path could not be continued on the other over the same store. (ITL-1491)
- **`Index` gives the element's token the type of the token list's items.** It typed the
  token again from its value, so a list item's type could change (a fixed-size list became a
  `large_list`). An element that is a null where the remaining token type is a list is
  refused with `InputValidationError` naming the column, on both paths. (ITL-1491)
- **A function pod's stream outside a job shows list-valued source-info tokens.**
  `pod(stream).as_table(columns={"source": True})` raised `ValueError: Unsupported Python
  type` when a data-tag that falls through the function had a list token. (ITL-1491)
