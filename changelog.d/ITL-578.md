### Added

#### `polars.DataFrame` and `polars.Series` values (ITL-578 #286)

A function pod can take or return a `pl.DataFrame` or `pl.Series`; before, declaring one
raised `TypeError: No LogicalType or LogicalTypeFactory registered`. The logical types
`orcapod.polars.dataframe` and `orcapod.polars.series` store the value with Polars' own `write_ipc` in
`large_binary`, and a value reads back with exactly the schema it was stored with (column
order, struct field order, every dtype parameter). `Object`, `Int128`, `UInt128` and Polars
extension dtypes raise `ValueError` naming the column when the value is stored.

The content hash (the cache key) is labelled `polars_dataframe_v1` / `polars_series_v1` and
covers everything a pod can observe as the value's logical content: row count, column names
and order, dtypes (struct field order, Enum categories, a `Categorical`'s `Categories`),
and values, where a null struct differs from a struct of nulls. Chunking, sortedness flags
and physical `Categorical` codes are not part of it. See *Polars DataFrame and
Series values* in the hashing reference. Storing a frame in a SQLite store is not supported yet (ITL-877).
