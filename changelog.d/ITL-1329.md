### Changed

- A pre-release no longer freezes the data context (ITL-1329). Only a final version runs the
  golden release step. A release candidate (`0.4.0rc1`; also `aN`, `bN`, `.devN`) carries
  the hashes intended to be final and is published without it: the Release workflow's gate
  checks instead that HEAD does not record the pre-release as a release.
  `generate_golden_hashes.py --release` refuses a pre-release. The tag check of earlier
  final releases still runs for every version. The GitHub Release of a pre-release is marked
  as one, and its notes say that it freezes nothing and that data stored with it is not
  guaranteed to be valid under the final release. The Linear release jobs do not run for a
  pre-release. The workflow's version must be in its PEP 440 normal form (`0.4.0rc1`, not
  `0.4.0-rc.1`). `RELEASING.md` has the checklist for cutting a candidate and the rule
  between a candidate and the final release: a golden value changes only for a blocking
  reason, with the developer's approval of the exact list, and a new candidate follows.
