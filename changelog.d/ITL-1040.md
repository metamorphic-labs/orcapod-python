### Fixed

- Async job runs no longer store an extra `_source_<column>` column for a data column dropped before a function pod, by the automatic select of `pod(stream)` or by an explicit `SelectDataColumns` or `DropDataColumns` (ITL-1040). `Data.drop` and `Data.select` kept the source info of the removed columns, and `Data.as_table(columns={"source": True})` still showed it. Sync and async runs now store the same pipeline records. No hash, record id or stored path changes. A Delta pipeline table written by an async run before this fix keeps the extra column, and rows written after the fix have null in it.
