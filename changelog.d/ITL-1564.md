### Breaking changes and migration

- A plain source over a job node's stored results now defaults to
  `derived_v1:<job path>:<hash label>:<node hash>` (ITL-1564). Pass an explicit
  `source_id` when a job name is unavailable or contains a separator.
- The full source id now enters the content hash of a plain derived source,
  including when you provide the name. Default source-cache paths and downstream
  pipeline-entry keys change. The origin job's stored results are still readable.
- Plain derived sources now emit one new system-tag pair and a fresh token for each
  data column. Both forms fold upstream system tags for record IDs by default.
  Explicitly positional `tags_as_data` sources keep positional IDs and receive
  their own content hash and default cache path.
  When a node has stored multiple versions of one input lineage, a read takes the
  most recent readable version. Rebuild downstream pipeline tables and caches in
  fresh storage. A separately configured result store can be reused.

### Fixed

- Derived source previews reject repeated lineage across all rows held by the
  origin, including rows outside the preview limit.
