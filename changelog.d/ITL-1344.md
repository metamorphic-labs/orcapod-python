### Fixed

- **A run warning no longer makes the run raise in a notebook on Python 3.12** — `job.run()`,
  `job.run_async()` and a job node's `run()` raised `ValueError: Module globals is missing a
  __spec__.loader` instead of warning when one of the run warnings fired
  (`RestrictedAggregationWarning`, `SourceCheckFailedWarning`, `RowFailuresWarning`) and the
  run was started from an IPython or Jupyter cell on Python 3.12: a restricted source feeding
  `group_by` always warns, so such a job could not run at all. The same call raised for other
  callers: `python -m package.module` (`ImportError`, Python 3.11 and 3.12), a module whose
  file got shorter after it was imported (`IndexError`, 3.11 and 3.12), a module made with
  `types.ModuleType` (`ValueError`, 3.12 and later), a module whose loader raises when asked
  for its source, and a script run with `-W error` (`DeprecationWarning`, 3.12). Orcapod
  handed the caller's globals to `warnings.warn_explicit(module_globals=...)`, which Python
  uses to find the line's source text and which raises in these cases. The three warnings
  are now issued by one helper that never passes them and registers the source with
  `linecache.lazycache` instead: the warning keeps its category, message, file and line, is
  still shown at every run, and still follows the user's filters; the line of a module with
  no file on disk (a zip import) is now shown on every Python version. (ITL-1344)
