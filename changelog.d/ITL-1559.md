### Breaking changes and migration

- Function pods that receive an invocation context now include the configured parameter
  name in their pipeline hash. Their pipeline tables and downstream tables that use the
  affected hashes have new `schema:<P>` paths, and downstream system-tag column names
  that incorporate those hashes change. The public idempotency key
  `InvocationContext.invocation_hash` also changes for the affected function pods
  and for downstream side-effect nodes whose pipeline hashes change. Tables written
  by earlier development versions remain at their old paths. There is no migration
  for these unreleased layouts.
  Side-effecting function nodes and tracked side-effect pods refuse to run when
  a completion table exists at that node's exact previous pipeline path. A
  tracked tap can reopen alongside a live sibling that owns the tap's former path.
  Result tables for context-taking function pods have a new `ctx:<parameter>`
  path component. Decorator caches also move context-taking results into the
  `side_effect_function` namespace. The pod and job caches refuse delivery if
  their exact previous result table exists. For a decorator cache, the old path
  was shared with plain calls. The check refuses delivery when a row there
  matches the configured function's signature hash. A different or missing hash
  cannot identify a legacy contextual result, and a plain result with the same
  hash cannot be distinguished from one. Saved jobs continue reading their
  original result tables.
  (ITL-1559)

### Fixed

- Loading a saved job restores context-taking function nodes, their stored results,
  and their downstream dependencies. (ITL-1559)
