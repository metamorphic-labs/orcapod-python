### Added

- Streams, recorded invocations, and job nodes expose `source_chain()`, `name_chain()`, and `node_hash()`. The node hash identifies a computation by its structure and input slot names, so it is available on an unbound pipeline. A polling source can report its node hash before its first batch supplies the schema. Existing pipeline and content hashes keep their values.

- A job loaded without an operator implementation still exposes its saved hashes. A loaded built-in `Index` can also report the new chains from its saved structure and single input. Operators whose input symmetry is unavailable report an error for the new chains.

### Fixed

- Source chains follow rebindings inside composite input bindings. Name chains can be read without fetching a polling source's rows, and downstream identities that need its missing schema report that they are undefined. Nested commutative groups use the pipeline hash's canonical input order.
- Identity accessors report an undefined identity when they would have to materialize a lazy upstream or hash raw Arrow rows. Plain derived sources, including cached bindings, report no source chain while an origin slot is unbound.
- Polling source chain reads use a memoized legacy content hash when available and report an undefined identity when they would have to call the polling implementation.

### Known limitations

- The new combined hashes raise an error when a commutative group drops content-equal inputs from its argument symmetry (ITL-1590). The legacy pipeline and content hashes remain available.
