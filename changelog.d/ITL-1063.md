### Fixed

- Repeated pipeline runs reuse completed operator work and retained row hashes when
  their input snapshots are unchanged. Sync execution preserves row objects across
  node boundaries; async execution reuses valid in-memory function results. Unknown
  or changing inputs, explicit invalidation and failed work remain subject to normal
  execution and recovery.
- A SpiralDB source retains a successfully read pinned snapshot for later sync,
  async and table reads. Construction remains lazy; partial, failed and cancelled
  reads do not publish a snapshot. Retention uses memory proportional to the snapshot;
  `batch_rows` bounds processing slices, not total retained memory. Construct a new
  source to read a newer table version.
