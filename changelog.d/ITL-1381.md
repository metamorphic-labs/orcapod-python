### Fixed

- A writable connector database no longer fails with `ArrowInvalid`
  when rows are queued for a table whose queued rows declare a column's nullability
  differently. The combined batch declares the column nullable. Combining declarations
  that disagree on a stored `NOT NULL` column is still refused. Queuing a null in a
  stored `NOT NULL` column is also refused, regardless of the incoming declaration.
  Rows holding a null where their own schema declares a column or nested field non-nullable
  raise `NullInNonNullableColumnError` when they are queued, before anything is stored.
  SQLite now rolls back the full upsert on failure. A flush drops rows it identifies
  as invalid and keeps the other attempted rows for retry. It also tries each table
  before reporting an error. Atomicity applies to each upsert. Table creation and
  writes to separate tables commit independently. Backend errors that do not identify
  a rejected row may leave the entire atomic batch queued.
  (ITL-1381)
