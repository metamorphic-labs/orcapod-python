### Breaking changes and migration

- A `datetime` value with a part below one microsecond is refused instead of truncated
  (ITL-1268). An output declared `-> datetime` is stored as `timestamp[us, tz=UTC]`, and a
  `pandas.Timestamp` with nanoseconds (what a function receives from a `timestamp[ns]`
  column) used to be stored without them. The same held for a source declared
  `datetime` given such a value. The function's row now fails with an `OutputTypeError`,
  and a source raises `SubMicrosecondDatetimeError` (a `ValueError`). Round or truncate the
  value explicitly first (`value.floor("us")` or `value.round("us")`). A value whose part
  below one microsecond is zero is stored exactly, as before.

### Fixed

- A naive `datetime` returned for an output declared `-> datetime` is refused with a message
  that says why and how to convert (ITL-1268). It used to read "returned datetime.datetime
  for output 'y', which is declared datetime.datetime: ValueError". The message now says the
  value has no time zone while the output is an instant, and shows how to attach a zone
  (`value.replace(tzinfo=timezone.utc)` when the wall time is UTC). It uses the same rule
  and wording as a source over Python values, which raises `NaiveDatetimeError` (a
  `ValueError`, as before). The mapping is unchanged: `-> datetime` is an instant, stored as
  `timestamp[us, tz=UTC]`, and an aware value of any zone is stored as its instant. A
  function over a column without a time zone attaches a zone to what it returns. A way to
  declare an output without a zone or with nanoseconds is ITL-1325. The function pods page
  ("Dates and times") states the mapping in both directions. The rule covers function
  outputs and the Python values of `DictSource` and `ListSource`; a `DataFrameSource`
  given a plain dict or list is not covered yet (ITL-1330).
- An aware `datetime` whose UTC offset has a part below one second is stored at its exact
  instant (ITL-1268). Arrow dropped that part of the offset: `datetime(2026, 1, 2,
  tzinfo=timezone(timedelta(seconds=1.5)))` was stored 0.5 s late, an offset of -1
  microsecond 999,999 microseconds early. Such a value is now converted to UTC before
  Arrow sees it. Every other value is handed to Arrow as before, so no other stored value
  changes.
