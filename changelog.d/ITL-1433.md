### Added

- Function-node pipeline records now include the recording job's run ID
  (`__pipeline_run_id`) and the UTC recording time (`__recorded_at`). Standalone
  node runs store a null run ID. Entries require an output. Recomputing a lost
  result creates a new entry with its own recording metadata. Within a run,
  sync execution reuses the first entry for an identical input without system
  tags. Async execution can schedule both copies before either entry is
  available and record them separately.

### Breaking changes and migration

- Pipeline tables written by 0.4.0rc1 through 0.4.0rc3 lack these columns and
  must be rebuilt before appending, even if they contain no rows. The layout
  remains `pdb_v1`.
