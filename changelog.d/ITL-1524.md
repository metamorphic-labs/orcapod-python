### Breaking changes and migration

- Function pipeline tables now use the `pdb_v3` layout. They store and hash input
  provenance under `_input_source_<column>`, which changes the instance and record
  IDs for rows with input tokens. Earlier pipeline tables are reported and left
  intact. A normal function run can use the existing result tables to rebuild its
  pipeline records. Functions with an invocation context refuse earlier pipeline
  tables because they cannot safely match those side-effect completions.

### Fixed

- Stored function outputs keep the function's provenance when their names match
  input columns. Fall-through data-tags keep their input provenance.
