### Fixed

- **A stream lists its tags in one order** — for a table not laid out in tag order (a
  source over columns `a, b, c, x` with `tag_columns=["c", "b", "a"]`),
  `output_schema()` listed the tags in the table's column order while `keys()` and the
  rows list them in tag order, so every operator over such a stream predicted its tags in
  another order than it produced them (`DropTagColumns(["a"])` predicted `("b", "c")` and
  produced `("c", "b")`). The tag schema now follows the tag order, so `output_schema()`,
  `keys()`, predicted schemas and rows agree, and a saved job writes its tag schemas in
  that order. No row, table column order, stored table, hash or stored path changes, and
  a job saved before loads with the same hashes. (ITL-1365)
