### Changed

- **A job run hands an operator node's kept table to the nodes after it** — an operator node
  in a job keeps its run's output as a table built from its rows, and the sync orchestrator
  then built the same table again from the same rows for each node that reads it. The node
  now returns its rows carrying the table it built (`RowsWithTable`), and the orchestrator
  wraps that table for each successor (`_materialize_upstream`). The table is built once
  instead of once per successor plus once to keep. Every successor's input is the same:
  columns, types, row order, system tags, source info, pipeline and content hashes. No hash,
  stored table or output changes. First stage of the table transport between job nodes
  (`docs/dev/specs/itl-1347-job-table-transport.md`). (ITL-1347)
