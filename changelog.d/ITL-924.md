### Changed

- A Python float or wider NumPy float supplied for a column declared `numpy.float32`
  in a Python schema issues one `ValueConversionWarning` per process and declared
  type. This covers sources, datagrams built from Python values, dict-backed
  updates, and new columns declared with Python types. The warning depends on
  the supplied type. Arrow still converts each value as before. Pass
  `numpy.float32` values or declare the column `float` to avoid the warning.
  Existing Arrow values and validated function outputs do not issue it (ITL-924).

### Fixed

- Distinct Python float keys in `dict[numpy.float32, V]` or elements in
  `set[numpy.float32]` can become equal when stored, causing an entry to be lost
  on readback. For example, `1e-50` and `2e-50` both become `0.0`. In a Python
  schema these collisions raise `CanonicalOrderError` naming the column, both
  inputs, and the stored value. Optional keys and elements are covered. Valid
  entries keep their existing order and Arrow conversion (ITL-924).

### Known limitations

- Narrow float widths known only through Arrow are outside the diagnostic
  scope. This includes updates of materialized datagrams, even when a Python
  schema originally declared the columns, and Arrow-declared source columns.
  These paths keep their existing table conversion and can still store
  colliding keys or elements. NumPy scalar subclasses whose storage can call
  custom `__float__` methods also retain their existing key and element handling
  (ITL-924).
