### Added

- `SpiralDBTableSource(..., connector=<SpiralDBConnector>)`: sources of one project and
  dataset that are given one connector use its SDK client, so they sign in once and read the
  dataset's schema table once per version of it (ITL-1457). It is part of no identity, is not
  saved, and changes no row, order or hash; a later source given the connector does not read
  and decode the same version of the schema table again, so it does not notice that doing so
  would now fail. Without the argument a source makes its own connector, as before.

### Fixed

- `SpiralDBConnector` copies the `overrides` it is given, and `to_config()` returns a copy, so
  changing either dictionary later cannot make it save or report another service address than
  the one it reads (ITL-1457).
