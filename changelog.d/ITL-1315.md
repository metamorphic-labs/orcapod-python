### Fixed

- A `CSVSource` built with an explicit Arrow `schema=` now saves it in its configuration
  (`to_config()`, and so `PipelineJob.save`) and `from_config()` reads the file with it again
  (ITL-1315). Before, the reloaded source inferred the types from the file: a nullable column
  could come back non-nullable, a narrow width (`int16`, `float32`) wide and a string of
  digits an integer, and the reloaded source had another content hash and pipeline hash under
  the same source id. The saved entry, `"schema"`, holds each field's Arrow type text (nested
  fields with their names and nullability) and the names of the nullable fields; a source
  built without `schema=` saves no entry, and a configuration without one (inferred types,
  or a file saved before this release) loads as before. No hash changes.
- An explicit schema that carries Arrow metadata (on a field at any depth, or on the schema
  itself) cannot be saved: `to_config()` and `PipelineJob.save` raise `ValueError` naming the
  field, and no file is written. Build the schema without the metadata to save the source.
