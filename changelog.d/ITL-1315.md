### Fixed

- A `CSVSource` built with an explicit Arrow `schema=` now saves it in its configuration
  (`to_config()`, and so `PipelineJob.save`) and `from_config()` reads the file with it again
  (ITL-1315). Before, the reloaded source inferred the types from the file: a nullable column
  could come back non-nullable, a narrow width (`int16`, `float32`) wide and a string of
  digits an integer, and the reloaded source had another content hash and pipeline hash under
  the same source id. The saved entry, `"schema"`, holds each field's Arrow type text (nested
  fields with their names and nullability) and the names of the nullable fields; a source
  built without `schema=` saves no entry, and a configuration without one (inferred types)
  loads as before; a present entry of any other shape is
  refused (`ValueError`; `PipelineJob.load` refuses the file). No hash changes.
- An explicit schema that carries Arrow metadata (on a field at any depth, or on the schema
  itself) cannot be saved: `to_config()` and `PipelineJob.save` raise `ValueError` naming the
  field, and no file is written. Build the schema without the metadata to save the source.
- A `CSVSource` with an explicit `schema=` now reads each cell's text as its column's declared
  type (ITL-1322). Before, it read the file with inferred types and cast them, so the text was
  altered or lost: `007` under a string type was stored as `"7"`, `1e3` as `"1000"`, a long
  number as `"1.2345678901234567e+19"`; a decimal went through a double (`1.005` was stored as
  `1.00`); and a value of another type was converted (`1.0` to the integer `1`, a bare number to
  a timestamp, a date and time to a date). **A source with an explicit schema may therefore
  store different, correct values than before, and so have other row hashes; a value of
  another type now raises `ValueError` naming the column.** In a string column only an
  unquoted empty field is null: a quoted `""` is the empty string, and `NA` or `null` are kept
  as text (before, an empty cell and these markers became null when the whole column looked
  empty); binary columns follow the same rule. Other columns read the usual null markers as
  null. Under a float type a finite value too large for the type raises instead of becoming
  an infinity (a spelled `inf` is kept). A declared type pyarrow's CSV reader cannot parse
  (`decimal32`, `string_view`, a nested type) raises, naming the column. A source without
  `schema=` is unchanged.
