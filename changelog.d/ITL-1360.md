### Breaking changes and migration

- **`SyncPipelineOrchestrator.run` takes `held` instead of `held_rows`** — a job's sync run
  passes the held nodes' output streams (`held: Mapping[node, StreamProtocol] | None`); a
  subclass that overrides `run` with the old `held_rows` parameter fails with `TypeError`
  before the override runs: rename the parameter to `held` and read each held node's rows
  from its stream (`iter_data()`). The async orchestrator still takes `held_rows`.
  (ITL-1347, ITL-1360)

### Changed

- **A job node's `execute` returns its output stream** — `execute` of a source, operator,
  function and side-effect job node (and of the node protocols) returned the node's rows as
  a list of (tag, data) pairs, and the sync orchestrator rebuilt a table from them for each
  successor. It now returns the node's output stream, which the sync orchestrator hands to
  every successor. Where that table is provably the rows' own, the node gives it
  without making the rows: a node bound to an instance of exactly a library source kind
  whose table is its rows (`TABLE_IS_ROWS`, never inherited by a subclass), and an
  operator node whose result yields its rows from exactly an `ArrowTableStream`, in that
  stream's row order (REPLAY: its stored table), each only when the rows report the
  node's data context and every system tag is non-null text, as rows give it. Every other
  output (a narrower bind, a subclass or another kind of bound stream or result, rows of
  another data context, system tags of another type, a table the whole-table build
  cannot use, a result with no row, a held node, a function or side-effect node) is the
  node's rows, unchanged, whose table is built where a successor reads it, as before; a
  retained one keeps only its rows once every successor has read it.
  `OrchestratorResult.node_outputs` holds each node's output stream: its rows
  (`iter_data()`) are the rows the node returned, and its table is built when the table
  is first read (`as_table()`, a successor's edge); on the sync path a held node gives
  the stream of its held rows, and the async path still sends a held node's rows as the
  run's plan took them (`held_rows`). Every successor's input is unchanged: columns,
  types, row order, system tags, source info, pipeline and content hashes, and an error
  surfaces where and when it did. No hash, stored table or output changes. An operator
  node's table is built once, for what it keeps and for every successor, instead of once
  to keep and once per successor. The first two stages of the table transport between
  job nodes (`docs/dev/specs/itl-1347-job-table-transport.md`).
  (ITL-1347, ITL-1360)

### Added

- **`arrow_schema()` and `arrow_types_declared` on every stream** — `StreamProtocol`,
  every stream and every source node state the Arrow schema of the columns a job node
  passes on (user tags, system tags, data and source info), without reading, computing or
  polling a row. System-tag and source-info fields are stated nullable and a source-info
  field's type as the declared token type: a complete table decides both from its values,
  so a consumer must not rely on them. A `null` column keeps the `null` type of a table
  with no rows. `arrow_types_declared` is false where the rows decide the types: a stream
  that cannot type itself without rows (an unbound slot, a `PollingSource` not yet
  polled), a narrower bind, and an output held as its rows. Such a description gives the
  declared names and types, in no guaranteed order. (ITL-1360)
