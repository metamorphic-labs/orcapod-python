### Changed

- **A job node's `execute` returns its output stream** — `execute` of a source, operator,
  function and side-effect job node (and of the node protocols) returned the node's rows as
  a list of (tag, data) pairs, and the sync orchestrator rebuilt a table from them for each
  successor. It now returns the node's output stream, which the sync orchestrator hands to
  every successor. A node bound to an instance of exactly a library source kind whose
  table is its rows (`TABLE_IS_ROWS`, never inherited by a subclass) gives its source's
  Arrow table, and an operator node whose result yields its rows from exactly an
  `ArrowTableStream` its result's table in that stream's row order (REPLAY: its stored
  table), each in the form a table built from the rows has, without making the rows.
  Every other output (a narrower bind, a subclass or another kind of bound stream, an
  operator result of another stream kind, a table the whole-table build cannot use, a
  result with no row, a held node, a function or side-effect node) is the node's rows,
  unchanged, whose table is built where a successor reads it, as before. `OrchestratorResult.node_outputs` holds each node's
  output stream: its rows (`iter_data()`) are the rows the node returned, and its table is
  built when the table is first read (`as_table()`, a successor's edge); on the sync path
  a held node gives the stream of its held rows, and the async path still sends a held
  node's rows as the run's plan took them (`held_rows`). Every successor's input is
  unchanged: columns, types, row order, system tags, source info, pipeline and content
  hashes, and an error surfaces where and when it did. No hash, stored table or output
  changes. An operator node's table is built once, for what it keeps and for every
  successor, instead of once to keep and once per successor. The first two stages of the
  table transport between job nodes (`docs/dev/specs/itl-1347-job-table-transport.md`).
  (ITL-1347, ITL-1360)

### Added

- **`arrow_schema()` and `arrow_types_declared` on every stream** — `StreamProtocol`,
  every stream and every source node state the Arrow schema of the columns a job node
  passes on (user tags, system tags, data and source info), without reading, computing or
  polling a row. System-tag and source-info fields are stated nullable and a source-info
  field's type as the declared token type: a complete table decides both from its values,
  so a consumer must not rely on them. A `null` column keeps the `null` type of a table
  with no rows. `arrow_types_declared` is false where the rows decide the types: a stream
  that cannot type itself without rows (an unbound slot, a `PollingSource` not yet
  polled), a narrower bind, and an output held as its rows. Such a description gives the
  declared names and types, in no guaranteed order. (ITL-1360)
