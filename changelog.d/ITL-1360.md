### Changed

- **A job node's `execute` returns its output stream** — `execute` of a source, operator,
  function and side-effect job node (and of the node protocols) returned the node's rows as
  a list of (tag, data) pairs, and the sync orchestrator rebuilt a table from them for each
  successor. It now returns the node's output stream, which the sync orchestrator hands to
  every successor as it is: a source node gives its source's Arrow table, and an operator
  node its result's table (REPLAY: its stored table), each in the form a table built from
  the rows has, without making the rows. `OrchestratorResult.node_outputs` holds each
  node's output stream, and a held node gives the stream of its held rows. Every
  successor's input is unchanged: columns, types, row order, system tags, source info,
  pipeline and content hashes. No hash, stored table or output changes. This replaces the
  rows that carried their table (`RowsWithTable`) of the first stage. Second stage of the
  table transport between job nodes (`docs/dev/specs/itl-1347-job-table-transport.md`).
  (ITL-1360)

### Added

- **`arrow_schema()` and `arrow_types_declared` on every stream** — `StreamProtocol`,
  every stream and every source node state the Arrow schema of the columns a job node
  passes on (user tags, system tags, data and source info, in row order), without reading,
  computing or polling a row. System-tag and source-info fields are stated nullable, since
  a table decides their flags from its values; a `null` column keeps the `null` type of a
  table with no rows. `arrow_types_declared` is false only for a stream that cannot type
  itself without rows (an unbound slot, a `PollingSource` not yet polled), whose schema is
  converted from its Python schema. (ITL-1360)
