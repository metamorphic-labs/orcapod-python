## `src/orcapod/pipeline/job.py` — reading a loaded `PipelineJob`

### LJ4 — A saved job does not record an operator node's cache mode
**Status:** open
**Severity:** medium
**Issue:** ITL-1163

`OperatorJobNode.from_descriptor` reads `descriptor.get("cache_mode", "off")`, but `PipelineJob.save` never writes `cache_mode` into an operator node's descriptor. Every loaded operator node is therefore `OFF`, whatever mode it ran in. A load-only run of a loaded job runs the operator again over its rebuilt inputs instead of replaying the table a `LOG` or `REPLAY` node stored. The stored rows are still read by `node.get_all_records()` and `node.as_source()`, and by `REPLAY` when the caller attaches that mode again after loading. This is the case in plain mode and with data-tags (found while adding operator-node storage of streams with data-tags, ITL-1019; `tests/test_pipeline/test_saved_job_with_data_tag_operator_nodes.py` attaches `REPLAY` again). A fix writes the mode into the saved descriptor, which is a saved-file format question.
