## Pipeline identity

### TC1 — Graph identity and source binding share one key
**Status:** in progress
**Severity:** high
**Issue:** ITL-1559

A graph key derived from bound data cannot distinguish two slots bound to one source.
It also cannot follow a slot through a rebind while identifying the same computation
(ITL-1442, ITL-1427).

Step 1 computes separate structure, source and name chains. The new node hash is
available even when no source is bound. The graph and persistence still use their
existing hashes. ITL-1590 tracks the remaining structural dependency on source equality
when a commutative operator receives equal-structure inputs.

The step 1 follow-up serializes binding and chain reads. Saved jobs retain the
existing file format. An operator loaded without its implementation cannot report
the new chains until a later step records input symmetry. Schema-less polling sources
report a node hash before their first batch, including when wrapped in a cache.

**Fix:** The execution protocols require both combined identity accessors. The
combined hashes raise when the legacy commutative grouping drops content-equal
arguments, including in downstream nodes. Recovering the lost order remains ITL-1590.
Source chains follow rebindings inside composite bindings and source wrappers.
Downstream chain reads never poll for a missing schema. Mixed nested input groups
use the pipeline hash's canonical ordering.
The new accessors refuse to build lazy upstream rows or hash raw Arrow rows.
Plain derived source chains, including cached bindings, are absent while an origin
slot is unbound.
