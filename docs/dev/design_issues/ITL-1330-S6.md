## `src/orcapod/core/sources/`

### S6 — A `DataFrameSource` given Python values typed them through Polars, silently lossy
**Status:** resolved
**Severity:** high
**Issue:** ITL-1330

`DataFrameSource` passed whatever it was given to `pl.DataFrame(data)`, so it also built from
a dict or a list of Python values, and Polars inferred the types before the data context's
type converter saw anything. The converter's rules did not apply on that path:

- `DataFrameSource({"id": [1], "v": [pd.Timestamp("2026-01-02T03:04:05.123456789Z")]})`
  stored `timestamp[us, tz=UTC]`: 789 nanoseconds dropped, no error.
- A naive `datetime` was stored as an unzoned `timestamp[us]`, while the same value in a
  `DictSource` raises `NaiveDatetimeError`.

Anything else Polars can make a frame of built too: a string (one row, a column named
`column_0`), a generator, a NumPy array, a Polars `Series`.

**Fix:** `DataFrameSource` accepts data frames only (developer, November 28, 2026, option
(a): "we could expand it in the future if we really need to"). A data frame is a pandas
`DataFrame`, a Polars `DataFrame`, or an object that exports an Arrow C stream or C array of
a struct (a pyarrow `Table`, `RecordBatch`, `RecordBatchReader`, a struct array, a frame of
another library). Everything else is refused when the source is built, before anything is
read or built, by one rule, `data_frame_source._require_data_frame`: a `TypeError` that names
the type given and its remedy (`DictSource` / `ListSource`, or `pl.DataFrame(data)` for a
caller who wants Polars' typing; `to_frame()` for a `Series`, `collect()` for a `LazyFrame`).
A Polars `Series` exports an Arrow C stream and is excluded explicitly. Every supported input
builds as before (`tests/test_core/sources/test_data_frame_source_inputs.py` pins the default
source id measured before the change).

Not changed, a separate decision: a pandas `DataFrame` whose column has dtype `object` is
still typed from its values by the pandas-to-Arrow conversion, so `pd.Timestamp` values with
nanoseconds in an `object` column are stored `timestamp[us, tz=UTC]` with the nanoseconds
dropped, and naive `datetime` values in one as an unzoned `timestamp[us]`. A typed
`datetime64` column (pandas or Polars, any unit, zoned or not) is stored exactly as given.
