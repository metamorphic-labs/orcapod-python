## Hash labels — file content hashes (ITL-1155)

### FH1 — File hashing exposed algorithms outside the hash label rule
**Status:** resolved
**Severity:** high
**Issue:** ITL-1155

File hashing accepted several digest names as labels, plus `hash_path`, which
hashed the path string. A file content hash label needs to identify the full
procedure that produced it.

**Fix:** Use SHA-256 over the file bytes and keep the `sha256` label. Reject
other algorithms in built-in and custom file hashers and cache writes. Use fixed SHA-256 implementations and read-only algorithm properties. Verify
custom hasher declarations and digest widths, then compare custom file and
directory results to the library's SHA-256 and `directory_v1` computations.
Route registered File and Directory content handlers through this verification.
Subclass handlers can still describe their semantic identity with `Encoded`.
Validate directory ignore patterns before sharing them across both traversals.
Check custom hasher and cacher declarations after a cache lookup. Direct cache
reads for other labels miss, and clearing a persistent cache preserves
historical rows. Remove the algorithm selection from cache warming and drop
the `xxhash` dependency.
