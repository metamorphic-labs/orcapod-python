## `src/orcapod/core/nodes/function_node.py`

### FN4 — A row recomputed in a later session rebuilt its tag from Python values
**Status:** resolved
**Severity:** high
**Issue:** ITL-1298 (related: ITL-1295)

A function job node whose results are ephemeral finds, in a later session (a new job over
the same database with a new, empty ephemeral database), stored pipeline entries whose
results are gone: cross-session misses. `_load_cached_entries` held an `EmptyData`
placeholder for each, with a `Tag` rebuilt from the stored row's Python values and no
schema, so the tag's types were inferred again: `int8` and `float32` came back as 64-bit
types (another tag hash), and a struct tag raised when read ("Complex unions ..."). The
measurement found the wrong tag reached no presented row and no stored table: every public
read computes the row again first, on the same base entry, or leaves the placeholder out.

**Fix:** `_fetch_joined_records` keeps each miss row's one-row Arrow table from the pipeline
table (`_JoinedRecords.empty_taginfo_tables`), and `_load_cached_entries` builds the tag
from its tag and system-tag columns, with the stored types: the miss row's tag has the
first session's types and tag hash, and a struct tag reads. Runs, counts, presented and
stored rows, record ids, entry ids and paths are unchanged; no golden value moves. Tests:
`tests/test_pipeline/test_cross_session_miss_tags.py` (the placeholder's tag is visible
only in the loaded entries, which the test reads directly).
