## `src/orcapod/core/nodes/function_node.py`

### FN4 — A row recomputed in a later session rebuilt its tag from Python values
**Status:** resolved
**Severity:** high
**Issue:** ITL-1298 (related: ITL-1295)

A function job node whose results are ephemeral finds, in a later session (a new job over
the same database with a new, empty ephemeral database), stored pipeline entries whose
results are gone: cross-session misses. `_load_cached_entries` held an `EmptyData`
placeholder for each, with a `Tag` rebuilt from the stored row's Python values and no
schema, so the tag's types were inferred again: `int8` and `float32` came back as 64-bit
types (another tag hash), and a struct tag raised when read ("Complex unions ..."). The
wrong tag reached no presented row and no stored table: a run computes the row again first,
on the same base entry, and `head`, a cache-only send and a load-only run leave the
placeholder out. It was visible through the public cache facade, `get_cached_results`,
which returns the placeholder's `(tag, EmptyData)` without computing.

**Fix:** `_fetch_joined_records` keeps each miss row's one-row Arrow table from the pipeline
table (`_JoinedRecords.empty_taginfo_tables`), and `_load_cached_entries` builds the tag
from its tag and system-tag columns, with the stored types and without the storage-only
data-tag mark (`without_tag_kind_marks`, as for a stored row read into a stream): the miss
row's tag, as `get_cached_results` returns it, has the first session's fields, types and
tag hash, and a struct tag reads. Runs, counts, presented and stored rows, record ids,
entry ids and paths are unchanged; no golden value moves. Tests:
`tests/test_pipeline/test_cross_session_miss_tags.py`, through `get_cached_results`.
