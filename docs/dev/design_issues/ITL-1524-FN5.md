## `src/orcapod/core/nodes/function_node.py`

### FN5 — Stored function outputs could report the input's provenance
**Status:** resolved
**Severity:** high
**Issue:** ITL-1524

A function job node delivered its own token for an output that shared an input's
name. On readback, the joined table kept the pipeline input's token under that
name and suffixed the result token. A downstream function could then record a
second instance of the same row with the input's provenance.

**Fix:** The stored join presents the result table's tokens for the function's
declared outputs. A fall-through data-tag keeps its own input token, and the
pipeline table retains its input tokens for instance identity. Plain
`DerivedSource` token policy is tracked separately with the identity work in
ITL-1564.
