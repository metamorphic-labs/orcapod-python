## `src/orcapod/core/nodes/function_node.py`

### FN5 — Stored function outputs could report the input's provenance
**Status:** resolved
**Severity:** high
**Issue:** ITL-1524

A function job node delivered its own token for an output that shared an input's
name. On readback, the joined table kept the original input's token under that
name and added a suffix to the result token. A downstream function could record
a second instance with the wrong provenance.

**Fix:** The `pdb_v3` pipeline table and the instance ID preimage use the same
`_input_source_<column>` fields. The joined read presents the result table's
`_source_<column>` fields for outputs and restores the usual stream names for
fall-through data-tags. Plain `DerivedSource` token policy is being considered
with the identity work in ITL-1564.
