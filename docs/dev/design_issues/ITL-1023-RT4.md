## `src/orcapod/core/nodes/source_node.py`

### RT4 — A loaded job keeps a referential column's pending type for one role only
**Status:** open
**Severity:** medium
**Issue:** ITL-1200 (found on ITL-1023, PR #342)

A loaded job keeps a slot column's type as pending when it names a user class not registered in the process (`_keep_saved`), and restores it when a source of that class is bound (`_restore_pending_types`). Pending types are keyed by column name only, so for a referential tag (one name in the tag and the data schema) the data entry replaces the tag entry. After binding, the tag schema still holds the saved text as a `str`, and `_fit` can refuse a matching source with a type-mismatch message instead of the unregistered-type message. Readers to change: `_restore_pending_types`, `_take_saved_state_of`, `_pending_nullable_columns`, the `_fit` message lookup. Reported by CodeRabbit on PR #342; ITL-1200 fixes it.
