## `src/orcapod/core/nodes/function_node.py`

### RT3 — A fall-through node records the plain result's hash, so a lost ephemeral result misses downstream
**Status:** open
**Severity:** medium
**Issue:** ITL-1199 (found on ITL-1023, PR #342)

A function node whose pod lets referential tags fall through (`ReferenceFallThroughPod`) stores in its pipeline record (`OUTPUT_DATA_HASH_COL`) the hash of the plain function output, taken before `with_fall_through` adds the referenced columns. The downstream node receives the augmented output, and its result cache is keyed by that output's hash. With ephemeral results (`NodeConfig(is_result_ephemeral=True)`) lost in a new session, the node emits an `EmptyData` token carrying the stored hash; the downstream lookup misses and raises `EphemeralResultMissingError` although its result exists. The ordering is the same in the sync, async and channel paths. Persistent results are not affected. Reported by CodeRabbit on PR #342; ITL-1199 fixes it.
