## `src/orcapod/core/data_function.py` — returned values not checked against the declared type

### NR1 — `-> None` with no output keys was refused; a value returned with no outputs was dropped
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1257 (related: ITL-1258)

`extract_function_schemas` (`utils/schema_utils.py`) has a branch for a function annotated
`-> None`: with no output keys it means no outputs, with output keys it is refused. The
branch was never reached, because `typing.get_type_hints` reads `-> None` as `NoneType`:
`-> None` with no output keys was refused ("has a return type annotation, but no return
keys were specified"), while `-> None` with one output key was accepted with an output
column of type `NoneType`. Separately, a function with no output keys that returned a
value had the value dropped silently (`parse_function_outputs`).

**Fix:** `extract_function_schemas` reads `NoneType` as `-> None`, so `-> None` with no
output keys means no outputs (as no return annotation does) and `-> None` with output keys
is refused at construction. A function with no output keys that returns a value other
than `None` raises `NoOutputsDeclaredError`, an `OutputTypeError`, at call time, on the
sync and the async path (developer: "declared `-> None` (or lack of any return type) should
be treated as empty return"). Tests: `tests/test_core/data_function/test_none_return.py`.
In the same change, a positional-only parameter is refused at construction (ITL-1258;
`test_positional_only.py`).
