## `src/orcapod/core/operators/batch.py`

### BA1 — `Batch` changed values by rebuilding its lists from Python
**Status:** resolved
**Severity:** critical
**Issue:** ITL-1281 (related: ITL-1250, ITL-1248)

`Batch` read its input with `table.to_pylist()` and rebuilt every list column from the
Python values (`arrow_utils.build_aggregated_table`). A `time64[ns]` value lost its
nanoseconds, a `date64` value off midnight came back at midnight, and a float32 signaling
NaN came back quiet.

**Fix:** a batch is consecutive rows, so each list is a slice of the input's column: the
lists are built from the input's Arrow arrays and offsets
(`arrow_utils.aggregated_list_array`), every value bit for bit, in the input's row order.
Batch sizes, drop modes, system-tag folds and types are unchanged; no golden value moves.
`build_aggregated_table` and `list_array`, the builders from Python values, are gone. Tests:
`tests/test_core/operators/test_batch_values.py`.
