## `src/orcapod/pipeline/job.py`, orchestrators, node write paths — database write failures

### BL3 — A job omitted independently attached database objects from its final commit
**Status:** resolved
**Severity:** high
**Issue:** ITL-1383

A caching operator attached to a separate database object returned its new rows
from memory while its log was still buffered. The whole-job final commit flushed
only the job's database views. Independently constructed objects could have separate
pending writes even when they used the same storage location.

**Fix:** After the job's usual commit, the run flushes each additional database
object with node writes left to commit, once. It also makes this attempt when
execution fails, keeping the original error. Load-only runs skip the commit. A
failed flush clears the current rows of the nodes that ran and leaves previously
held rows available.
