## `src/orcapod/databases/` — appending another logical type

### LI2 — Delta lost logical types or refused identical appends for nested extension columns
**Status:** resolved
**Severity:** critical
**Issue:** ITL-1372

Delta could store an extension array in a list item, map key or value, or
dictionary values as plain Arrow storage. A list of structs could keep the
struct child's identifier but rename the list item, causing an identical
append to fail. With extension metadata on storage fields beneath lists or
maps, an identical append could fail once the extension was registered.

**Fix:** Delta checks the incoming schema before buffering. It refuses Arrow
extension types anywhere within list items or dictionary values, or directly
as map keys or values. It refuses storage fields carrying an extension
annotation anywhere beneath a list or map, regardless of registration. It
names the affected columns and points to plain storage or the in-memory
database. Arrow extension types on struct children, including under another
struct or a struct-valued map item, keep their existing write and read paths.
