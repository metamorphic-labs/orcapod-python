## `src/orcapod/databases/` — appending another logical type

### LI2 — Delta lost logical types or refused identical appends for nested extension columns
**Status:** resolved
**Severity:** critical
**Issue:** ITL-1372

Delta could lose a nested Arrow extension's identifier or store a field as a
different type. Some nested forms accepted a first write and then refused an
identical append. Others committed a table a fresh handle could not read.
The problems also occurred inside the storage of an extension type.

**Fix:** Delta accepts a logical type only as a whole top-level column. It
checks the schema and nested annotations on individual chunks before buffering.
The check walks extension storage and refuses both actual and annotated nested
types regardless of registration, with the column and nested path. Orcapod's
logical containers and user classes keep child values in plain Arrow storage
within one top-level extension, so they do not need nested Arrow extensions.
