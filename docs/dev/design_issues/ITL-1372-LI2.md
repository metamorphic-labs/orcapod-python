## `src/orcapod/databases/` — appending another logical type

### LI2 — Delta lost logical types or refused identical appends for nested extension columns
**Status:** resolved
**Severity:** critical
**Issue:** ITL-1372

Delta could store an extension array in a list item, map key or value, or
dictionary values as plain Arrow storage. A list of structs could keep the
struct child's identifier but rename the list item, causing an identical
append to fail. With extension metadata on nested storage fields, an identical
append could fail once the extension was registered. An actual extension field
with ordinary metadata also refused an identical append. A sibling requiring
type recording could change type or make the stored column unreadable, since
the extension bypasses type recording for the whole column.

**Fix:** Delta checks the incoming schema before buffering. It refuses Arrow
extension types anywhere within list items or dictionary values, or directly
as map keys or values. It refuses nested storage fields carrying an extension
annotation regardless of registration, actual nested extension fields with
other metadata, and nested extension columns that require type recording.
It names the affected columns and points to plain storage or the in-memory
database. Supported struct children, including under another struct or a
struct-valued map item, keep their existing write and read paths.
