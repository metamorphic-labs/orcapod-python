## `src/orcapod/core/sources/cached_source.py`

### RT8 — CachedSource neither marks nor checks the data-tags of its cache table
**Status:** open
**Severity:** medium
**Issue:** ITL-1215 (found on ITL-1023, PR #342)

A stored table states which of its tags are data-tags (ITL-1019): function and operator nodes mark data-tag columns with field metadata and check the marker against the node on every read. `CachedSource` writes its cache table unmarked and, on read, takes the data-tags of the wrapped source without comparing them with the table. With an explicit `cache_path` the table location does not depend on the source's content hash, so a source with a data-tag and a plain source over the same data can share one table: the plain reader drops the data role of the column, and the reverse read gives a plain tag a data role. The fix marks the table on write (`mark_data_tags`), compares the stored marker with the data-tags of the merged stream on read and refuses a disagreement, and refuses a cache database that keeps no field metadata for a source with data-tags. Reported by CodeRabbit on PR #342.
