## `src/orcapod/core/operators/semijoin.py` — nested columns and string/large_string keys

### SJ4 — `Join` and `SemiJoin` (sync) changed values by carrying every column through Polars
**Status:** resolved
**Severity:** critical
**Issue:** ITL-1284 (related: ITL-1250, ITL-1281)

The sync paths of `Join` (`static_process`) and `SemiJoin` (`binary_static_process`)
joined `pl.DataFrame(table)` with the other input and converted the result back to Arrow,
then cast it to the input types. Every column went through Polars, and Polars changes or
refuses some Arrow types on the way: a `date64` value off midnight came back at midnight
(1 ms became 0 ms), as data and as a key, in a list and in a struct; a `decimal256` column,
at the top level or nested, made Polars panic ("operator does not support primitive
`Int256`"), which no caller can catch; a map or interval column, even as data only, failed.
Key matching was correct. The async paths do not use Polars and were exact, so the two
paths disagreed for these types.

**Fix:** Polars only decides which rows match. It is given the key columns, prepared by
`core/operators/arrow_keys.py` (the one place: a logical type as its storage, a dictionary
decoded, a temporal value as its integer, `float16` as `float32`, a view as its large
variant, `decimal256` as four 64-bit limbs, through lists, fixed-size lists and structs),
and row numbers; every output column is taken from the input tables by those row numbers
(`take`), so every value is the input's, bit for bit, and a data column of any type passes
through. A key whose type has no rule there (a map, an interval, a union, a list view) is
refused with `InputValidationError` naming the column (`base.require_matchable_key`) on
both paths, before rows are matched, never passed to Polars. Output layout, row order, system
tags, key nullability and the type-disagreement refusals are unchanged; no golden value
moves. Tests: `tests/test_core/operators/test_join_arrow_values.py` and the
`*_exact_values` cases of `test_async_sync_equivalence.py`. `GroupBy` keeps its own copy
of the preparation until ITL-1281; `MergeJoin` is ITL-1281.
