## `src/orcapod/core/sources/`

### S5 — `PollingSource`'s identity is not settled; provisional in data context v1
**Status:** open
**Severity:** medium
**Issue:** ITL-1316 (related: ITL-1314, ITL-1311)

The source identity inventory (ITL-1311) found that `PollingSource`'s identity is not
settled: its default `source_id` is the semantic hash of the implementer's own `identity()`,
which nothing holds stable, and its content hash, `(impl.identity(), sorted tag columns, key
columns)`, leaves out the `source_id` and the declared schema, so two polling sources with
different names share a content hash.

Developer decision, November 21, 2026 ("make polling source provisional"): it is not repaired
before 0.4.0 and not deleted. It is provisional (ITL-1314): `PROVISIONAL_SOURCES` lists it,
building one issues `ProvisionalHashWarning` once per process, and no golden value pins it
(the three pins it had were removed; a golden case cannot declare a provisional source). Its
identity is decided in ITL-1316, after which it leaves the list and its golden values are
added.
