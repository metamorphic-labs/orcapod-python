## `src/orcapod/core/nodes/source_node.py`

### BT2 — A narrower bind with one data-tag placed that tag twice
**Status:** resolved
**Severity:** high
**Issue:** ITL-1420

A slot bound to a narrower source gives its rows in the declared form (`_DeclaredForm`),
which puts each column group (tags, system tags, data, source info) in its declared order.
A data-tag is in the tag group and in the data group, and was placed by both. With tags
declared `j, k` and exactly one of them a data-tag, one position was filled twice and
another column was lost: the slot's `as_table()` and `head()` raised `KeyError` (a
duplicate field), and its typed zero-row table held the duplicate and lacked the other
tag. An operator's description is derived from that table. A job's run read the slot's
rows another way and was not affected. Other arrangements happened to give a valid order.
The same defect made a mixed-role source bound in another column order (data-tag first)
fail when the slot's table was read (ITL-1245, found by the several-item test audit).

**Fix:** `_declared_positions` keeps the placement it gave whenever every column comes
out once, so no order that worked changes; where it would place a column twice, it places
data-tags with the tags only. Every arrangement (two tags, two data columns, no data-tag,
either one or both, both tag orders) is tested for the slot's table, head and typed
zero-row table and for a run on each orchestrator, and the several-item bind sweep now
includes the mixed-role source on both orchestrators (its strict expected failure for
ITL-1245 is removed).
