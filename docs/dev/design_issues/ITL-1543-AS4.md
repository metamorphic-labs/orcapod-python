## `src/orcapod/core/operators/join.py` — system-tag provenance

### AS4 — Join could lose record IDs or attach ID pairs to the wrong operand
**Status:** resolved
**Severity:** high
**Issue:** ITL-1543

The ID sorter grouped operands by the printed provenance path. Distinct full
pipeline hashes with the same shortened suffix could exchange source and record
IDs, even though other system tags stayed with their operands. A tied Join
could also sort an existing record ID into a position with no declared record-ID
field and drop it. For equal source IDs, the old sort raised on the missing
record ID. The null-safe sort let the affected operand order silently lose it.

**Fix:** Join uses full pipeline hash ties to constrain pair sorting for schema
prediction, sync, standalone row channels, and record batches. Within a tie
with different sets of system-tag fields, whole declarations and their values
move together. For ID-only ties with missing fields, the fullest declarations
take the earliest positions. Stored entry IDs change where the previous
sorting produced incorrect system-tag fields or values.
