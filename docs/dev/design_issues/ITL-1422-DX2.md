## `src/orcapod/logical_types/registry.py` — exit after reading a logical type

### DX2 — A process that read a logical type could abort or hang at interpreter exit
**Status:** resolved
**Severity:** high
**Issue:** ITL-1422

The C++ destructor of a Python-defined Arrow extension type (`PyExtensionType`) takes the GIL.
A dataset scan deserializes the type of each logical column on Arrow's worker threads, with the
native filesystem too (ITL-892), and each deserialization made a new type object. A worker that
drops the last reference to one after the scan returned, while the interpreter finalizes, is
stopped by CPython inside a destructor: SIGABRT on Linux with Python 3.11 and 3.12 (seen in two
release runs), a hang elsewhere. The work is done by then, and stored rows are complete.

Measured on Linux x86_64 with 4 CPUs, Python 3.11 and pyarrow 23.0.1, eight children at a time,
Arrow's threads at `SCHED_IDLE` so that their clean-up trails the scan. Aborts of processes that
load a job and read a logical type: 40 of 600. With the types kept alive: 0 of 600. With
`use_threads=False`: 27 of 600, so serial scans do not help. A job with an `int` output: 0 of
300. Without Orcapod: a Python extension type 51 of 600, a plain column 0 of 600, pyarrow 26.0.1
68 of 600 (and 30 of 600 at normal priority), so no version pin helps.

**Fix:** a logical type's extension class has one instance, shared by every read, with a
reference that is never given back (`logical_types/arrow_lifetime.keep_for_process`), so no
worker can drop the last one. The instance is per concrete class, extension name, storage type
(nested field metadata included) and serialized metadata, which is what Arrow tells types apart by on read (`KeptInstances`, the
metaclass of a class `make_arrow_extension_type` makes): a subclass is a type of its own, with
its own Arrow hooks, and its instances are kept the same way. `tests/test_logical_types/test_extension_type_lifetime.py` checks
the property for every registered type. An extension type a user writes as a class is not
covered; `make_arrow_extension_type` is.
