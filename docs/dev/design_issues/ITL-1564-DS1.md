## `src/orcapod/core/sources/`

### DS1 — Plain derived source IDs omit the origin job
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1564

Two jobs with different names can store equal-hash nodes whose derived sources share
an ID, even though the jobs store their rows separately.

**Fix:** Use the job name and labelled node content hash in a plain derived source's
default ID. Use the root source content identity, which includes the full ID and Arrow
schema identity. A read stamps one new system-tag pair and fresh source-info tokens,
using a record id folded from the row's upstream pairs. For stored versions of one input
lineage, the most recent readable record is selected. The origin's stored tables keep
their provenance. Derived previews validate all held source rows before displaying a
slice, so a repeated lineage has the same result as a full read.
