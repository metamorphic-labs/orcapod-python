## `src/orcapod/core/operators/merge_join.py` — Arrow types

### MJ4 — `MergeJoin(A, B)` and `MergeJoin(B, A)` gave tied values' source info in argument order
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1241 (related: ITL-1281)

`MergeJoin` was documented as commutative and sorted each merged list by value. Two equal
values kept argument order, so their source-info list followed the order of the arguments
while both orders had one identity: an operator cache or a function pipeline table could hold
different provenance for one identity.

**Fix:** resolved by ITL-1281 (MJ3): `MergeJoin` is ordered. `MergeJoin(A, B)` and
`MergeJoin(B, A)` are two operations with two identities, and every list of a row is in
argument order, so no tie exists.
