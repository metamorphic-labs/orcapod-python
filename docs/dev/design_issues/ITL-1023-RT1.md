## `src/orcapod/core/data_tags.py` — data-tags workshop slice (ITL-1023)

### RT1 — Data-tags are supported by part of the library only
**Status:** open
**Severity:** medium
**Issue:** ITL-1023

The workshop slice of data-tags (specification attached to ITL-1004) covers sources, function pods, `Join`, `MergeJoin` (since ITL-1194), `GroupBy`, `Batch` (since ITL-1017), select and drop, renames, filters, `DropNulls`, `SemiJoin`, `Pick`, `Index` and `TagBy` (`tag_by`, ITL-1175), which gives a data column the tag role. Everything else raises "not supported with data-tags yet" when a data-tag reaches it, instead of giving a wrong answer: any operator that does not declare `DATA_TAGS_ISSUE = None` (ITL-1022). Saving a pipeline or job, the function node's stored bindings, an operator node's stored results (`LOG`, `REPLAY`) and `DerivedSource` over a stream with data-tags are supported since ITL-1019. `PollingSource` keeps its tags plain. The identities of streams with data-tags are not frozen yet. The project's issues (ITL-1009 onward) land the full design and close this entry.
