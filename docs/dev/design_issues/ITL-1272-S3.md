## `src/orcapod/core/sources/`

### S3 — The default source id of a keyed in-memory source followed the order of its rows, and `ListSource` had an identity of its own
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1272 (related: ITL-1227, ITL-1311)

An in-memory source given no `source_id` takes a default built from the Arrow hash of its
whole table (`SourceStreamBuilder.build`), and that hash includes the order of the rows. A
source with key columns (`record_id_columns`) names its rows by their keys and its reload
compares them without order, yet the same rows in another order gave another default source
id and content hash, with no way to ask otherwise. Separately, `ListSource` had an identity
of its own (class, name, its elements in order, a hash of its tag function chosen by
`tag_function_hash_mode`, key columns): unlike every other source its content hash followed
its elements under a given `source_id` and did not depend on that `source_id` at all (two
`ListSource`s with the same elements and different names shared a content hash).

**Fix:** developer decisions, November 21, 2026 (replacing an earlier "always sort"
decision of November 19). `hash_in_key_order=True`, a keyword of the four in-memory sources
and of `SourceStreamBuilder.build`, hashes the table sorted by the key columns in key order
(`arrow_utils.key_row_order`, an Arrow `sort_indices` then `take`), after the keys are
validated; it is refused without key columns and with a `source_id`, and the rows are
presented as given. The default stays the table as given, since the order may be deliberate.
`ListSource` takes `RootSource`'s identity (class name, output schema, `source_id`, key
columns); `tag_function_hash_mode` and the tag-function hash are removed. Three golden
values moved, each a `ListSource`'s own content hash (developer approval, November 21, 2026).
Tests: `tests/test_core/sources/test_keyed_default_source_id.py`. A review of every
built-in source's identity is ITL-1311.
