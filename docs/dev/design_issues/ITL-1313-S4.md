## `src/orcapod/core/sources/`

### S4 — Default source ids of questionable stability: `DerivedSource(tags_as_data=...)`
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1313 (related: ITL-1311)

The source identity inventory (ITL-1311) found that `DerivedSource(origin, tags_as_data=...)`
built a default `source_id`, `tags_as_data:<label>:<hex>`, from a hash of the derivation (the
origin's content hash, the sorted mapping and `record_id_columns` when set), whose stability
is questionable: `record_id_columns=None` and `record_id_columns=()`, one key policy, gave two
different ids.

**Fix:** developer decision, November 21, 2026: "Rather than squeezing them in, let's simply
drop the "default" source id feature for all sources where the stability of the auto
computed source id is questionable. Simply make them throw an error if source id is not
provided." `DerivedSource` with `tags_as_data` and `node.as_source(tags_as_data=...)` (which
now takes `source_id`) raise `ValueError` without a `source_id`, before the origin is read;
`from_config` refuses a config without one before rebuilding the origin. `_derivation_hash`
and `DerivedSource._default_source_id` are removed. Plain `DerivedSource(node)` and
`node.as_source()` are unchanged (ITL-956). Tests:
`tests/test_core/sources/test_derived_source_tags_as_data.py`.
