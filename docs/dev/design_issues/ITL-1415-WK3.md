## `src/orcapod/databases/`

### WK3 — Appends accept changed field metadata inside extension storage
**Status:** resolved
**Severity:** high
**Issue:** ITL-1415

The append check skipped the nested fields of extension types. An append could
carry different field metadata inside a struct-backed extension and read back
with the held column's metadata.

**Fix:** Compare field metadata recursively in extension storage. Delta checks
the metadata held in its log against the incoming storage fields before enqueue
and also checks against the version loaded for a commit.

The Delta log has no field metadata for list items or map keys and values
inside extension storage. For committed rows, those annotations are unknown.
The initial Parquet footer can carry list item metadata, while later MERGE
footers can omit it.
