## `src/orcapod/core/operators/join.py` — async path

### RT6 — Reported: a merged float data-tag key may take 0.0 on one path and -0.0 on the other
**Status:** open
**Severity:** low
**Issue:** ITL-1202 (found on ITL-1023, PR #342)

CodeRabbit (PR #342) reported that when `Join` merges a float key that is a data-tag on at least one input and the inputs hold `0.0` and `-0.0`, the async path can take the data value from another input than the sync path keeps, so the sign differs between paths and between the tag and data roles. Not reproduced: 12 two-input, one-row cases (signs, plain or a data-tag on each side, both argument orders) under the sync and async orchestrators give the same value on both paths, in both roles. ITL-1202 tries the uncovered cases (three or more inputs, several rows per key, async arrival order) and either fixes the rule or adds the cases to `test_async_sync_equivalence.py` and closes this entry.
