# ITL-1467 — Report nodes skipped for unbound sources and open existing stores

## Reproduced on origin/main

Run `uv run python docs/dev/scripts/itl_1467/reproduce.py` on `5eb327ad`. A job
over a saved `DictSource` slot loads with the slot unbound. With either the
original in-memory database or a Delta database supplied, the downstream
function has zero rows and the summary says “nothing to do; every node holds a
current run.” Moving a relative Delta store and loading without an override
recreates the empty root in the current working directory. The stored view
returns zero rows and warns when read.

## Run summary

`PipelineJob._prepare_run` excludes unbound slots and their descendants before
`plan_run` applies the held-node state rule. The summary sees only the remaining
graph. An empty `plan.to_run` therefore cannot establish that every node was
held.

Carry the exclusion reasons through the job's shared run preparation and
completion paths. Propagate the unbound slot names through the saved graph and
include only restored job nodes in the result. Add
`RunSummary.skipped_unbound_sources: Mapping[str, tuple[str, ...]]`, keyed by
skipped node label with sorted, unique blocking slot names. Include unbound
slots themselves. Keep `RunSummary.nodes` and `NodeRunSummary.held` as the
function and side-effect row counts for the resolvable graph.
`ran_nothing` still means that no node was run.

When there are exclusions and no node ran, use this headline:

> Load-only run of job 'small': no nodes ran.

When a partial load-only run ran nodes and had no stored-result misses, use
`every available input had a stored result.` in place of
`every input had a stored result.` The stored-result miss headline stays the
same. Under the headline, in text and notebook HTML, list the excluded nodes
by label using this wording (both the node label and each slot name are
represented as Python strings):

```text
  'joined': skipped (unbound sources: 'memory')
  'memory': skipped (unbound sources: 'memory')
  'total': skipped (unbound sources: 'memory')
```

Use the same skip lines for partial full runs of freshly compiled jobs. The
held headline still applies when there are no exclusions.

## Reopen the existing database

`DeltaTableDatabase.from_config` always requests local root creation, including
when the read-only job loader calls it. Give Delta config resolution a way to
require an existing local root. Use it for both the saved job and separate
result databases, so a missing root takes the existing load-time warning and
override/bind path. Continue honoring explicit overrides, relative path
resolution, and remote Delta behavior. Retain creation defaults for callers
that reconstruct a store for writing. Apply the same rule when rebuilding a
saved source's Delta cache. A missing root or regular file leaves the binding
unavailable. An existing directory opens even if it has no Delta tables.
There is no saved-format, stored-path, or identity change.

## Verification

and two data columns, a function and an operator. Check the summary fields and
