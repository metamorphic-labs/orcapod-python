Prepared 2026-11-09 against `main` at `61d0f18e`. This is the ordered list of steps the
developer runs to publish `orcapod` 0.2.0, followed by the ITL-810 cut checklist with the

  ```bash
  (
    set -euo pipefail
    git switch main
    git pull --ff-only
    work=$(mktemp -d)
    uv build --out-dir "$work/dist"
    for v in 3.11 3.12 3.13; do
      env_dir="$work/smoke-$v"
      uv venv --python "$v" "$env_dir"
      py="$env_dir/bin/python"
      uv pip install --python "$py" "$work"/dist/orcapod-*.whl
      uv pip check --python "$py"
      (cd "$work" && "$py" -c "
  from orcapod import function_pod
  from orcapod.sources import DictSource
  src = DictSource(data=[{'name': 'Alice', 'age': 30}], tag_columns=['name'], source_id='people')
  @function_pod(output_keys='birth_year')
  def f(age: int) -> int:
      return 2026 - age
  print([(t.as_dict(), d.as_dict()) for t, d in f.pod(src).iter_data()])
  ")
      "$env_dir/bin/orcapod" --help
    done
    echo "SMOKE OK in $work"
  )
  ```

## Findings to decide on

None of these was changed in this PR. Findings 1–4 are addressed by ITL-827 (#277, open).

1. **There is no `LICENSE` file.** `pyproject.toml` declares MIT, but neither the
   repository nor the wheel contains the licence text. *Decided:* the license becomes
   proprietary; #277 adds the `LICENSE` file and declares
   `LicenseRef-Metamorphic-Proprietary`.
2. **The sdist publishes internal material.** It contains `superpowers/` (183 files of
   agent plans and specs), `tests/`, `CLAUDE.md`, `DESIGN_ISSUES.md`, `plan.md`,
   `notebooks/` and more — 3.3 MB against a 0.6 MB wheel. Earlier releases did the same.
   #277 limits the sdist to the package source and its metadata files.
3. **`basedpyright` is a runtime dependency.** A type checker is installed for every
   user. #277 moves it (and `typing_extensions`) to the `dev` group and removes the
   unused `pymongo` and `pyyaml`.
4. **`orcapod.__version__` does not exist**, although `orcapod/_version.py` is generated.
   #277 adds it.
5. **`v0.1.4` points at a commit on no branch.** `origin/patch` stops at `v0.1.3`.
6. **`CLAUDE.md` and `.zed/rules` still say "greenfield project pre-v0.1.0"** as the
   reason not to keep backward compatibility. After 0.2.0 ships with a migration tool,
   that policy deserves a deliberate restatement.
7. **`linear-sync` and `linear-complete` check out the default branch**, not the
   `branch` input. Harmless for a release from `main`; wrong for a hotfix release.
