## Findings to decide on

None of these was changed in this PR. The first is the only one worth settling before
the cut.

1. **There is no `LICENSE` file.** `pyproject.toml` declares MIT, but neither the
   repository nor the wheel contains the licence text, which the MIT licence requires to
   accompany copies. Every earlier release shipped the same way. Adding the file needs a
   copyright holder and year, which is the developer's call.
2. **The sdist publishes internal material.** It contains `superpowers/` (183 files of
   agent plans and specs), `tests/`, `CLAUDE.md`, `DESIGN_ISSUES.md`, `plan.md`,
   `notebooks/` and more — 3.3 MB against a 0.6 MB wheel. Earlier releases did the same.
   A `[tool.hatch.build.targets.sdist]` `include` list would narrow it.
3. **`basedpyright` is a runtime dependency.** A type checker is installed for every
   user. Moving it to the `dev` group is a dependency change and was out of scope.
4. **`orcapod.__version__` does not exist**, although `orcapod/_version.py` is generated.
5. **`v0.1.4` points at a commit on no branch.** `origin/patch` stops at `v0.1.3`.
6. **`CLAUDE.md` and `.zed/rules` still say "greenfield project pre-v0.1.0"** as the
   reason not to keep backward compatibility. After 0.2.0 ships with a migration tool,
   that policy deserves a deliberate restatement.
7. **`linear-sync` and `linear-complete` check out the default branch**, not the
   `branch` input. Harmless for a release from `main`; wrong for a hotfix release.
