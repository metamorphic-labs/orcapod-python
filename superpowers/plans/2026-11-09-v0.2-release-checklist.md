  The block runs in a subshell with `set -e`, so the first failing command stops it, and
  every run uses fresh temporary directories, so a leftover environment can never stand in
  for a clean install. The wheel is built from a clean, detached worktree at
  `origin/main`, so local commits or uncommitted changes cannot leak into it; the block
  prints the commit it built, which must be the commit you release. The pipeline result is
  asserted, so a wrong result fails the block instead of reaching `SMOKE OK`.

  ```bash
  (
    set -euo pipefail
    git fetch origin main
    work=$(mktemp -d)
    git worktree add --detach "$work/src" origin/main
    trap 'git worktree remove --force "$work/src"' EXIT
    echo "Building $(git -C "$work/src" rev-parse HEAD)"
    uv build --out-dir "$work/dist" "$work/src"
    for v in 3.11 3.12 3.13; do
      env_dir="$work/smoke-$v"
      uv venv --python "$v" "$env_dir"
      py="$env_dir/bin/python"
      uv pip install --python "$py" "$work"/dist/orcapod-*.whl
      uv pip check --python "$py"
      (cd "$work" && "$py" -c "
  from orcapod import function_pod
  from orcapod.sources import DictSource
  src = DictSource(data=[{'name': 'Alice', 'age': 30}], tag_columns=['name'], source_id='people')
  @function_pod(output_keys='birth_year')
  def f(age: int) -> int:
      return 2026 - age
  rows = [(t.as_dict(), d.as_dict()) for t, d in f.pod(src).iter_data()]
  print(rows)
  assert rows == [({'name': 'Alice'}, {'birth_year': 1996})], rows
  ")
      "$env_dir/bin/orcapod" --help
    done
    echo "SMOKE OK in $work"
  )
  ```

  Expected: no `--override`, no `--no-install-package`; the printed commit is the one
  you release; `uv pip check` reports no incompatibility; the pipeline prints
  `[({'name': 'Alice'}, {'birth_year': 1996})]`; the block ends with `SMOKE OK`.
  (Before ITL-134, `uv pip check` reported `orcapod requires pygraphviz>=1.14, but it's
  not installed`.)

  **Result, 2026-11-09 — pass, on this branch after merging `main` (`07e5a2ea`), merge
  commit `5982f099`.** macOS arm64, uv 0.13.7. Wheel `orcapod-0.1.3.dev33+g5982f0990`
  installed into clean venvs with no `--override` and no `--no-install-package`, on
  Python 3.11.18 and 3.12.15: `uv pip check` reported `All installed packages are
  compatible` (65 packages, `pygraphviz` not among them); the pipeline printed
  `[({'name': 'Alice'}, {'birth_year': 1996})]`; `orcapod --help` and
  `orcapod migrate --help` exited 0. The box stays unticked: repeat on the final `main`

1. **There is no `LICENSE` file.** `pyproject.toml` declares MIT, but neither the
   repository nor the wheel contains the licence text. *Decided:* the license becomes
   proprietary; #277 adds the `LICENSE` file and declares
   `LicenseRef-Metamorphic-Proprietary`.
2. **The sdist publishes internal material.** It contains `superpowers/` (183 files of
   agent plans and specs), `tests/`, `CLAUDE.md`, `DESIGN_ISSUES.md`, `plan.md`,
   `notebooks/` and more — 3.3 MB against a 0.6 MB wheel. Earlier releases did the same.
   #277 limits the sdist to the package source and its metadata files.
3. **`basedpyright` is a runtime dependency.** A type checker is installed for every
   user. #277 moves it (and `typing_extensions`) to the `dev` group and removes the
   unused `pymongo` and `pyyaml`.
4. **`orcapod.__version__` does not exist**, although `orcapod/_version.py` is generated.
   #277 adds it.
5. **`v0.1.4` points at a commit on no branch.** `origin/patch` stops at `v0.1.3`.
6. **`CLAUDE.md` and `.zed/rules` still say "greenfield project pre-v0.1.0"** as the
   reason not to keep backward compatibility. After 0.2.0 ships with a migration tool,
   that policy deserves a deliberate restatement.
7. **`linear-sync` and `linear-complete` check out the default branch**, not the
   `branch` input. Harmless for a release from `main`; wrong for a hotfix release.
