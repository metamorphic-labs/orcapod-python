## `src/orcapod/core/operators/` — Async execution

### SA1 — Sync and async runs gave different rows: meta columns, and a zero-row async operator node
**Status:** resolved
**Severity:** high
**Issue:** ITL-1080

The same pipeline run with the sync and the async orchestrator must give the same rows
(developer, November 13, 2026). Nine strict expected failures pinned differences:

* Eight operators disagreed on the inputs' `Data` meta (`__`) columns. Over a raw
  `ArrowTableStream` that lists `__` columns as data, the sync path of `MergeJoin`, `Batch`,
  `GroupBy` and `PolarsFilter` kept them while their barrier async path (`_rows_to_table`)
  dropped them; `SelectDataColumns`, `Index` and `Pick` did the opposite. Over a cached function
  pod's stream (rows carry `__computed`, `as_table()` hides it), `MapTags`, `MapData` and
  `DropNulls` dropped it on sync and kept it on async. `Join` already dropped meta on both paths
  (ITL-854, ITL-857). Row content hashes never differed: `Data.content_hash()` does not cover
  meta, and both orchestrators already stored operator rows without meta.
* An async operator node whose run produced no row read back a table built from the Python
  output schema (`int8` became `int64`; system-tag and source-info columns missing); the sync
  run kept the operator's own result.

**Fix:** the rule (developer, November 13, 2026): no operator carries its inputs' meta
columns, on either path, in rows and in the prediction. It lives in
`core/operators/meta_columns.py`: the unary and binary operator base classes (and `Join`) pass
their sync result through `without_input_meta` and their prediction through
`without_meta_fields`; every operator with its own `async_execute` sends its rows through
`WithoutMetaWriter`. A mode that carries meta forward across operators is ITL-867.
`OperatorJobNode.async_execute` taps its input channels (the first row, and the first row with
a `None` source-info token per column) and, when no row comes out, applies the operator to its
inputs rebuilt with no rows, exactly as the sync orchestrator rebuilds them
(`StaticOutputOperatorPod._materialize_upstream`, shared by both). No row content hash, record
id, pipeline hash or golden value moves.
