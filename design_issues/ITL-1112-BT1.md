## `src/orcapod/core/nodes/source_node.py`

### BT1 — Binding a source of other column types left every pipeline hash unchanged
**Status:** resolved
**Severity:** high
**Issue:** ITL-1112

`PipelineJob.bind(sources=...)` checked a source against its slot by column names only, and
assigning a source node's `bound_source` checked nothing. A source whose `x` is `str`, bound to
a slot declaring `x: int`, was accepted on a fresh and on a loaded job. Every pipeline hash is
built from the slot's declared schema, so none moved, while `output_schema()` passed the bound
source through: a downstream `MapData` reported `y: str` under the pipeline hash of `y: int`. A
run then sent `str` values to a function typed `int` and wrote its rows to the stored paths of
the declared types (`schema:<pipeline hash of y: int>/pdb_v2` and the pod's result table).

**Fix:** `SourceNodeBase.validate` compares, column by column, the source's tag and data schemas
with the declared ones: names, role (tag or data) and Python type, the inputs of the pipeline
hash, so an accepted bind never moves one. Column order and `optional_fields` are not compared;
neither enters the pipeline hash. The `bound_source` setter calls the same check before it
assigns, and `bind` checks every source before it changes anything, its database included.
`SourceSpecMismatchError` names the slot, the column and both types and is now an
`InputValidationError` as well as a `ValueError`. Two Arrow types that are one Python type
(`int32` and `int64`) are still not told apart (ITL-949). No hash, golden value or stored path
changed.
