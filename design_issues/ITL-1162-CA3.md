## `src/orcapod/databases/connector_arrow_database.py`

### CA3 — SQL connector databases cannot store list, struct and (on SQLite) timestamp columns
**Status:** open
**Severity:** high
**Issue:** ITL-1162

A `ConnectorArrowDatabase` over `SQLiteConnector` or `PostgreSQLConnector` cannot store a
function node's result table. Its `__pf_exec_executor_info` and `__pf_exec_extra_info`
columns are `large_list<struct<key, value>>`. The SQLite connector logged "Unsupported Arrow
type ...; mapping to TEXT" and then failed to bind a Python list (`sqlite3.ProgrammingError`)
at commit, after the function had run. The same table's `__pod_ts` (`timestamp[us, tz=UTC]`)
and a side-effect log's `executed_at` were stored as TEXT and read back as `large_string`.
`int8`, `int32` and `float32` columns read back widened, so the second write to the table
failed its schema comparison. PostgreSQL raises for list columns at `CREATE TABLE` and has no
column type for structs.

**Fix (refusal; developer ruling, November 16, 2026):** each connector states which columns
it stores, in one place (`DBConnectorProtocol.unstorable_column_reason(name, arrow_type,
primary_key=...)`): a column it reads back as written, with the same Arrow type in its large
variant. `ConnectorArrowDatabase.require_storable` raises `UnstorableColumnError` (connector,
column, Arrow type, reason, what to use instead) in `add_records`, before anything is
buffered. A function job node (its result table) and a side-effect job node (its invocation
log) ask the database when it is attached, so a job refuses them before anything runs, naming
the node. The connectors' silent TEXT fallback in `CREATE TABLE` now raises. Operator caches
and cached sources are refused at their write when a user column is unstorable.

**Open (the real fix, a later release):** store list and struct columns (for example as JSON
text read back as the same Arrow type) and timestamps on SQLite, so a function node can run
on a SQL connector database.
